「DevDay 真正卖的不是 Dots，是 Decisions API」

Decisions API 是 OpenAI 这一年最被低估的产品——它把「LLM 输出文本」拆成了「结构化决策」，schema 是受控的（有限候选 + 每个候选的概率），调用时间 150ms，比 Jev（TypeSafe AI）还要快。听起来像是某个边缘 API，但本质上是 OpenAI 第一次把 「agent 主循环里的分类/路由环节」从「用 LLM 生成自然语言然后 parse」里拆出来，单独做成一个廉价的、确定的、可审计的子调用。「智能体」这个词从此有了三层：主模型做规划、决策 API 做路由、小模型/规则做执行。这是 agent 经济被切成两层的原因——上面一层贵但负责，下面一层便宜且确定。

为什么重要（主编观点）：把这三件事横着看，2026 Q4 的 agent 栈正在被「工程化」压平：① 「agent = LLM + prompt + tools」的旧叙事彻底崩塌——DevDay 之后，「agent」是 「主模型 + Decisions API 路由 + 小模型工具 + 沙盒 + 审计」五件套，每个组件都有专门的厂商在做（OpenAI/Microsoft/ServiceNow/HuggingFace/Ai2）；② 「cost per task」的下降斜率从 18%/年加速到 40%/年——GPT-6.1 Sol 比 Astra 便宜 80%，加上 Decisions API 把每次路由降到 150ms，「每次 agent 决策的总成本」大约等于「一次小模型调用 + 一次决策 API 调用」，比「一次大模型调用生成 200 token 自然语言」便宜一个数量级；③ 「agent 训练」第一次走出 RLHF/RLAIF 的框架——ServiceNow AutoSynthData 用「教师 vs 学生」的失败/成功对生成任务，意味着 enterprise agent 可以在用户自己的 IM 上 post-train而不需要重新跑 SFT/RFT，这给「私有 agent」打开了一扇门。
对你意味着什么：① 如果你的 agent 现在还在用大模型生成自然语言然后 parse 出 JSON 来做路由——Decisions API / Jev 这类结构化决策接口是 2026 Q4 你应该优先试用的基础设施。把它换成 Decisions API 后，单次路由的 token 成本大约能从 0.005 降到 0.0005，主循环的总成本坍塌 70%。② 如果你的 enterprise agent 在某个垂直场景跑得不够好——AutoSynthData 给出了不需要重新人工标注的样本生成范式：让更强的教师模型帮你标注你模型的失败轨迹，4000 条样本大约能让 Gemma pass@1 涨 7 个百分点，比跑一遍 RLHF 便宜太多。③ 如果你的 agent 在做长上下文——Milos Kotova 的 KV-cache 分配方法（latent KV rank allocation）已经把 KV cache 的内存使用动态化，同一段长对话可以省 20-40% 的 GPU 显存，是这一周最值得读的两篇文章。

Microsoft Agent Framework：BUILD 2026 把 Agent Harness 抬到「一等公民」

P0 6/3 开源 Microsoft · Agent Framework · Harness · CodeAct · BUILD 2026 公告 · GitHub · Agent Harness GA

发生了什么：微软在 BUILD 2026 把 Agent Framework 1.0（4/3 GA）叠加了三层新东西：① Agent Harness 作为一等公民 GA——技能 / shell 命令 / 文件系统访问 / memory / middleware 全栈内置；② Foundry Hosted Agents——per-session sandbox、per-session 计费；③ CodeAct——把一连串工具调用折叠成单一沙盒程序，延迟 -52.4%、token -63.9%。

核心信号：OpenAI 走「API 形状」（Decisions API），微软走「runtime 形状」（Harness / Foundry / CodeAct）——两家今年的路线其实都在做同一件事：把 agent 从「写出来」变成「用现成的」。Build 2026 后 Azure 团队对外的标配叙事变成了「don't write a harness, use ours」。

为什么重要：过去 18 个月，agent 框架战场的核心矛盾是「写 framework 还是用 framework」。Build 2026 把这个矛盾解决了——微软直接告诉你「Harness 不要从零写，你写 skill 和 tool」。这个姿态变化比 Framework 1.0 GA 更重要：Framework 不再是 product，Harness 才是。CodeAct 的 52%/64% 折叠意味着 agent 的主循环成本曲线终于被微软自己攻破。

ServiceNow AutoSynthData：把 agent 的「失败轨迹」变成训练数据，4000 条样本让 Gemma pass@1 涨 7 个点

P0 10/2 训练 企业 ServiceNow · CoreAI · AutoSynthData · EnterpriseOps Gym · HF Blog 原文 · Ai-Brainer 解读

发生了什么：ServiceNow CoreAI 发布 AutoSynthData pipeline：① 跑目标模型在 EnterpriseOps Gym 上的失败轨迹；② 用更强的教师模型在相同任务上跑成功轨迹；③ 用「失败 vs 成功」对反向合成新任务；④ 用 positive/negative verification 校验可执行性；⑤ 把通过校验的样本用于 post-training。在约 4000 条合成任务上，Gemma 在 enterprise ops 任务上的 pass@1 从 25 涨到 32（+28% 相对）。

核心信号：AutoSynthData 的方法论其实和 NVIDIA Nemotron / DeepSeek-R1 蒸馏是同一条线——但 ServiceNow 的差异化在于「让失败自动长出新任务」而不是「让人标注已有任务」。这给 enterprise agent 的私有 post-training 打开了门。

为什么重要：enterprise agent 一直卡在两件事上：① 怎么拿到场景内的标注（隐私/合规/术语），② 怎么让模型在场景里变强（不是泛化）。AutoSynthData 把这两个问题合并成一个 pipeline：失败自动生成任务，教师自动标注，verifier 自动校验。这是企业级 agent「私有训练」第一次有了真正的工程范式，比 RLHF/RLAIF 友好得多（不需要偏好对，只需要成功/失败轨迹）。

Paperclip：开源（MIT）「AI 公司操作系统」——26K stars、两周内冲上 GitHub Trending 第一

P0 9/27 MIT 编排 Paperclip · paperclipai · Node.js · React · GitHub · 官网 · ExplainX 评测

发生了什么：paperclipai/paperclip 在 GitHub 上两周拿下 26K stars。本质是一个 Node.js + React 的 agent 编排层——「bring your own agents, assign goals, track work and costs from one dashboard」。核心抽象是「公司」：org chart、budget、governance、goal alignment、agent coordination。自带 OpenClaw / Claude Code / Codex / Cursor 适配器，自带审批门、自带预算控制、自带任务编排。

核心信号：如果说 Microsoft Agent Framework 是「Azure 的 agent 操作系统」，Paperclip 就是「独立开发者的 agent 操作系统」——而且是 MIT 完全开源。26K stars 两周这个数字本身就是信号：开发者已经不想再为「agent 怎么管」写胶水代码了，他们要的是 SaaS 化的开源版。

为什么重要：「agent team」这件事，过去 18 个月是靠 LangGraph / AutoGen / CrewAI 这种 framework 撑起来的；但「team 的运维」（谁在跑、花了多少钱、有没有越权）一直没有人做。Paperclip 把这个 gap 补上——它的「org chart」抽象甚至能映射到企业 HR 的角色（CEO、董事会、员工），这意味着 agent 第一次有了「企业级」管理面板。如果你的公司开始用 5 个以上 agent 做日常工作，这是你 2026 Q4 必看的一个仓库。

OpenAI DevDay 2026 三大主线：Dots + GPT-6.1 Sol + Decisions API

P0 9/29 OpenAI · DevDay · Dots · Sol · Codex Cloud · Recap · GPT-6.1 Sol 介绍 · BenchLM 总结

发生了什么：OpenAI 在 DevDay 2026 一口气放了 20+ 项公告，最值得拆的是三件套：

  • Dots：永久在线 agent，可被指定身份持续运行任务。本质是「GPT-6 系列的 harness 化产品」，不是新模型。
  • GPT-6.1 Sol：near-Astra 智能，API 输入/输出价格仅 GPT-6 Astra 的 1/5。定位是「生产级 agent 主循环的默认模型」——比 Astra 便宜，比 Sonnet 5.5 便宜，比 Gemini 4 Argon 便宜。
  • Decisions API：受限决策接口，输入候选清单 + 上下文，输出选中的答案 + 概率。150ms 延迟，preview 状态。

核心信号：GPT-6.1 Sol 把「Astra 级别的智能」打到「便宜到能当主循环」的价位；Decisions API 把「分类/路由」这种「不需要用 LLM 生成自然语言」的环节拆成专门 API。这两个动作加起来，等于宣告了 agent 经济正式进入「分工时代」。

为什么重要：Decisions API 是这一周被讨论最少、影响最大的产品。它的真正含义不是「又一个 API」，而是「OpenAI 正式放弃了让 LLM 做所有事情」——主模型负责规划/生成，Decisions API 负责「在有限选项中选一个」这种高 QPS、低延迟、低成本的子任务。Jev 已经在做的事，OpenAI 用自家品牌做了出来，agent 基础设施的格局从此变化。

⚡ 小模型 & 效率革命

Milos Kotova：24 小时内连发两篇 KV-cache 工程化文章，把小模型推理推到「不必等下一代硬件」的临界点

P0 10/5 KV-cache 小模型 Milos Kotova · Hugging Face Blog · KV-cache KL budget · Latent KV rank

发生了什么：Hugging Face 博客同一作者在 24 小时内连发两篇：① 「Allocating latent KV-cache memory across transformer layers」——把 KV cache 的层间分配做成「KL 散度校准预算」，动态决定每层该用多少 cache；② 「Reducing dropped tokens in a small MoE model」——用 latent rank 分配缓解 MoE 小模型的 token 丢弃问题。

核心信号：两篇文章指向同一件事：小模型推理的内存占用不是「hardware-bound」，而是「policy-bound」。换句话说，在同一张 GPU 上，通过动态分配 KV cache 和优化 MoE token routing，能多塞进 20-40% 的请求。

为什么重要：小模型在 2026 Q3 之前的故事是「4-bit 量化 + GGUF + Ollama」，Q4 的故事正在变成「动态 KV cache + 智能 MoE routing」。前者是「把模型压扁」，后者是「把运行时的内存用精」——两者叠加意味着 24GB 显存卡跑 30B Q4 模型不再是「勉强能跑」而是「留有冗余」。这是端侧 agent 跑 30B 模型变成「工程现实」的临界点。

P0 10/2 开源 MoE Ai2 · Allen Institute · OlmoCore 3 · 官方博客 · TechTimes 解读

New Survey：Agent 推理的「混乱现状」——单 agent 工具使用 ≠ 多 agent 协调

P1 9/29 综述 推理 theRevision · Survey 解读

theRevision 周一发布新综述：把「agentic reasoning」做了清晰切分——单 agent 的工具使用（tool use） 和 真正的多 agent 协调（coordinated multi-agent） 是两件不同的事，前者用 LLM function calling 就能做，后者需要专门的通信协议 / 共享状态 / 冲突解决机制。

为什么重要：这个切分把过去 18 个月「agent」这个词的混乱终结了——你买的产品如果只做 function calling 那是「tool-augmented LLM」，不是「multi-agent system」。下次供应商来找你推销 agent 时，先问它「你做的是 single-agent tool use 还是 coordinated multi-agent」。
