🔥 今日头条

NVIDIA AVO：同一个 Claude Opus 5，arc-agi-3 public set 从约 30% 到 100.00 RHAE

8 月 21 日，NVIDIA 公布 Agentic Variation Operators（AVO）。官方明确写道：Claude Opus 5 直接运行的约 30% 只是 ARC Prize 单独报告的模型级 high-reasoning baseline；换成 AVO 后，模型通过文本化 64×64 环境观察、persistent memory、supervisor、tool use 和 grounded feedback，在 ARC-AGI-3 的 25 个 public environments、183 个 levels 上拿到 100.00 RHAE，共使用 6,624 次环境动作。作为参考，VISTA 报告 7,542 次动作完成同一 public set，少约 12%。

为什么重要：这不是“Claude Opus 5 突然学会了 AGI”，而是一个干净的实证提醒：agent 产品测试必须测整套系统。在长任务里，memory 决定什么能穿过上下文，supervisor 决定是否及时换路，tool/feedback 决定模型能否从错误假设中恢复。昨天的日报刚写“harness 即产品”，今天就有了新的公开证据。

重要限定：NVIDIA 自己也声明这不是 controlled ablation；AVO 与 VISTA 在 backend、observation、memory、context management 上都不同。结果只适用于 25-environment public set，不适用于 semi-private/private competition sets。因此“可重复 100%”不能写成 AGI 突破，但“系统层设计可把同一模型从约 30% 推到 100%”这个结论非常扎实。

对 agent 开发者的具体建议：

  • 不要再用“换一个更强 model”作为唯一优化轴；给现有 agent 补上 trajectory memory、stagnation detector、supervisor 和 grounded validation，先做同模型同任务 A/B。
  • 评测同时记录 pass rate、工具调用、动作效率、重复探索和 supervisor 介入次数。100% pass 但 100K token 的 system，未必比 80% pass 且高效的系统更可部署。
  • 若做 ARC 这类 hidden-set 风格评测，把“公开集调参”和“隐藏集泛化”彻底分开；把 public set 当 regression set，而不是产品成绩。

Cross-task skill transfer：把“整段任务摘要”拆成 subtask skill，迁移才可靠

arXiv:2608.20274 在 3 个 benchmark（AppWorld、OfficeBench、KramaBench）和 11 个模型上做受控研究，比较 task-level / subtask-level 与 text / code 两种 skill 表示。结论很清楚：task-level skill 大多把 agent 拉回 no-memory baseline 以下；subtask-level skill 平均提升表现；同一抽象层级下，text skill 比 code skill 平均高 2.9（subtask）或 1.4（task）个百分点。

论文还提出 execution-free 的 skill utility = specificity × abstractness：只拿 skills 和 task descriptions 就能预筛，过低或不相关的 memory 不必在真实任务上“试毒”。按 utility 排序后，最高组的 success 从最低组的 22.8% 升到 31.0%（subtask-level agent）；task-level agent 则是 14.0% → 24.5%。

为什么重要：它把“写更多 skill”从玄学变成 memory-system 问题。skill 越像一整段工作日志，越容易和原任务绑定；粒度适中的局部经验，才可能在未来任务里复用。code skill 看起来更可执行，但 text skill 往往更跨任务、更便宜、更不容易锁死环境细节。

Actionable：把 agent 的 reflection 输出从“整单总结”改成“已验证的 subprocedure + 输入信号 + 成功条件 + 失败条件 + 可迁移边界”；每条 skill 运行时计算 specificity / abstractness，过期或低 utility 的不进上下文。先用 20–50 条历史任务做 A/B，别直接扩到全量 memory。

Task-CoEvolve：harness 优化不再每轮跑完整 validation set，评估次数减少 80%

Task-CoEvolve 将 harness code 与 validation task set 共同演化：优先抽样“不同 harness 容易分歧”、即靠近当前能力边界的任务，再用 sampling-aware estimator 比较各轮。官方结果显示，online text classification 用约 7% budget 就接近 Full Search、20% 时甚至超过；Terminal-Bench 2.1 在保持接近 Full Search 表现下，把搜索评估成本降低 67–80%。

为什么重要：Agent harness 调优最大的隐藏成本往往不是训练，而是 sandbox、终端或浏览器里“每个 candidate 跑几十条”的评测。若固定 100 条全跑，优化 20 轮就是 2,000 次；动态选 20 条就是 400 次，正确率还可能更高。harness 已从“一次性骨架”变成持续编译的系统。

Actionable：建立 capability-frontier 任务集：每轮先跑 10–20 条分歧最大的 case；只有候选 harness 都打平或无法区分时再扩大预算。把 evaluation budget 当超参，记录 token、wall time、sandbox time 和 final score，避免“便宜 80%”只是把长任务裁短。

MidTool：20.3B token 的 tool-use mid-training，4B/8B base model 在 SFT 与 RL 后持续受益

MidTool 用 web、PDF、code、API、MCP skills 和 document-grounded workflow 构造 20.3B-token / 11.22M-sample 的 MidTool-Mix，并设置两条互补 synthesis branch：context-grounded augmentation 教模型从混乱资料识别 tool affordance、参数和流程；native agentic trajectories 教它实际执行与恢复。Qwen3-4B-Base 和 Qwen3-8B-Base 在固定后续 SFT/RL recipe 下，于 BFCL、τ²-Bench、MCP-Universe 上均改善。

意义：tool use 不是“prompt 写几个 JSON schema”就能稳定得到的能力，它需要一套训练先验——识别边界、ground 参数、组合调用、从不完整信息恢复。论文 ablations 也显示去掉任一 branch 都会掉点；通用 tool-use mid-training 改善 schema grounding / workflow composition，但对 deep search 这类强探索任务帮助有限。

Actionable：如果你在做本地 tool-use model，先把 20.3B 全量照搬通常不划算；更实际的是从真实 API/MCP 文档、失败 trajectory 和环境验证器做 100M–1B domain mixture，再固定 SFT/RL recipe 做对照。

Task Model Induction：把员工操作轨迹变成可审计、可复用的“任务模型”

Stanford / CMU 的 TMI 不再假设员工一次只做一件事，而是从 screenshots、鼠标和键盘事件中发现交织的 latent tasks，再为每个 task 分离 hierarchical objective 与 control-flow procedure。论文报告 task grouping 与 ground truth 的 ARI/agreement 达 0.974，重建 74.9% execution steps；由此生成的 skills 在 held-out task accuracy 上比最强 baseline 高 30.0%。

意义：企业 agent 的“技能”不一定靠模型自省生成，也可以从真人示范中 process mining。下一步的差异化很可能是：谁能把混乱、跨窗口、夹杂隐私的桌面操作，稳定提炼成可审计 SOP，谁就有企业 workflow 数据资产。

Actionable：在录制前先做 PII 脱敏，把 email、客户名、token、剪贴板列入不可采集项；只保留 app、语义动作、artifact 引用和 objective。skill 必须带 provenance、录制版本、人工 reviewer，禁止直接把截图和键盘文本送进共享 registry。

MCP 新 roadmap：agent identity、progressive tool discovery、server-initiated events 正式进入优先级

8 月 22 日，MCP Core Maintainers 发布新版 roadmap，把未来方向压缩为五块：agentic messaging primitives、HTTP-native transport、agent identity / enterprise security、improved primitives、SDK DX。最值得 agent 开发者关注的有三点：

  • Tasks / subscriptions/listen / progress notifications 统一后，server 可用 webhook 或 channel 反向推动长任务；
  • 100+ tools 不再全部塞给 model，开始 progressive discovery，先给小入口，再按对话收窄；
  • 云端 agent 不再只拿人的 OAuth：要用 DPoP、Workload Identity Federation、token exchange 建立 agent identity 和 delegation chain。

为什么重要：MCP 正从“发现一个 tool 调一下”升级成 agent operations layer。没有 identity、异步 push 和渐进发现，跨服务 long-running agent 很难审计、授权和恢复。

Actionable：做 MCP server 时现在就加 tool catalog / capability index；生产 client 把最终解析后的 tool arguments 和 destination 写进 trace；为 outbound push / merge / payment 设计 human approval 或 policy gate，不要等新 spec 发布。

Munder Difflin 在 HN 爆火：数字克隆办公室，真实价值在 hive/memory/worktree

Munder Difflin 8 月 22 日在 HN 获得 244 points / 113 comments，仓库当前约 3,663 stars。它把 Claude Code、Codex、Grok、Kimi、Qwen、OpenCode、Pi、Copilot CLI、Cursor 等包成“团队成员”，提供 shared memory、mailbox、blackboard、append-only log、per-agent worktree、approvals、budgets、telemetry 和 circuit breaker；MIT 开源，BYOK / local LLM / cloud 均可。

我的判断：像素办公室只是好传播的 skin。真正值得借鉴的是“角色 / mailbox / single-committer worktree / 预算与熔断”这套 runtime contract，以及“把一个 CLI agent 变成可被监督的长期节点”。社区争论也很准确：视觉办公室可能很好玩，但不是长期 agent 的必需 UI；pipeline 与 scoped permission 才是核心。

⚡ 小模型 & 效率革命

Daedalus-150M：先为 CPU 设计架构，再谈量化——2048 context 达 1.76× 解码

Daedalus-150M 把 18 个 block 中仅 6 个保留 full attention，另外 12 个换成 memory 恒为两个 timestep 的 short convolution。4-bit 下，模型在 2,048-token context 解码比同数据、参数匹配的 dense attention baseline 快 1.76×，比一个外部同尺寸模型快 2.08×；chosen quality metric 高 0.81%、downstream tasks 打平、文件小 6.3%。模型用 59.9B token 训练，Apache-2.0。

为什么重要：现在太多小模型只是“大模型架构压到很小”。Daedalus 反过来从单用户、CPU、streaming decode、long context 出发，用固定状态卷积切断 KV cache 随长度增长。最有价值的是：速度曲线随 context 增长而扩大，而不是靠少训一点数据硬瘦下来。

现实边界：150M 远不到通用 agent planner 的可靠底座；paper 也承认原生 4-bit 有质量损失、部分卷积 channel 训练后 inert、vocabulary 偏大。因此它不是“1.76× 的 GPT 替代品”，而是 routing、intent classification、local preprocessing、隐私过滤或极窄任务模型的架构样本。

Actionable：端侧项目不要只比较 Q4 与 Q8；把 context-length × tokens/s 做成二维 benchmark。150M–350M 特别适合做本地 router，1B+ 才考虑多步 tool use。

Learning When to Think：1.5B reasoning model 自适应 NoThink / Short / Long，平均响应少 41%

Adaptive reasoning 把首个 token 设计成三档模式选择：NoThink、Short、Long，并在 GRPO 内用不同长度 reward 学 routing，不另设 router。MATH500 held-out accuracy 为 0.782 vs base 0.796，只损失 1.4 个百分点，平均 response length 从 4,796 token 降到 2,811（-41%）；GSM8K 上甚至减少 76% token 且准确率高于同等响应长度 baseline。

为什么重要：test-time compute 不应是一个全局 slider。简单问题仍启用 max reasoning，浪费的不只是钱，还会让 agent loop 更慢、更容易偏航。1.5B 能把计算预算变成按问题难度分配的 policy，是 agent router 的原生形态。

Actionable：先不训练模型，也可做轻量 rule router：短分类 / 检索抽取默认 no-think，代码修改 / 规划进入 short，复杂 debug / 多约束进入 long；按 task type 记录 success / token / time，三周后再替换为 learned router。

Faraday：27B 专用 science agent 在“复现论文”上胜过 Claude Opus 4.8 / GPT-5.5——但别把窄域结果外推成通用小模型胜利

DeepMind alumni 创办的 Inherent 在 8 月 14 日公布 Faraday / Replica，8 月 22 日被 TechCrunch 重新报道。Faraday 是 Qwen3.6-27B，经 long-horizon RL 后把 GPT-5.5 Codex 当 tool；Replica 含 100 篇 ML / AI-for-science 论文的 310 个复现任务。Inherent 报告它在各论文类别都优于 Claude Opus 4.8（Claude Code harness）与 GPT-5.5（Codex harness），held-out 新研究上更稳。

为什么重要：它支持“通用小 planner + 强 coding executor + domain-specific RL / rubric judge”可能比纯堆参数更有效。27B 模型不是靠 token 数量硬压 frontier，而是把“研究品味”压进一个可迁移 policy。

必须保留的 caveat：这是公司自建 benchmark、自研 rubric judge 主导的结果；TechCrunch 报道本身也明确说，这只是复现旧论文，不代表创新新科学。公开代码、数据与独立复现仍决定可信度。正确的结论是“specialization + 强 tool + 好 judge 是可行架构”，不是“27B 全面击败 GPT-5.5”。

Actionable：不要训练 27B；先复现结构：路由小模型 + 强 executor + 可执行 verifier + 按任务 rubric 的 judge。复现 benchmark 必须保留 hidden set、人工盲评和 executor failure attribution。

📡 广角扫描

MaliciousSkillBench：7,505 个恶意 skill，现有检测器 source-disjoint Macro-F1 仅 0.653–0.665

MaliciousSkillBench 汇总 13 个公开来源，规范化后得到 9,740 个 Skill（7,505 malicious / 2,235 benign），并定义 4,588 个 structural families。3 个 learned detectors 在随机划分上 Macro-F1 0.882–0.932，换到 source-disjoint 直接降到 0.653–0.665。最强 TF-IDF SVM 保持 95.6% malicious recall，却产生 62.4% benign FPR；现成 scanners 则在 recall 与 false positive 之间各有权衡。

为什么重要：Skill registry 越大，供应链攻击面越大；今天多数“skill 安全扫描”测的是同源文本，未必能识别换源改写、模板家族或新 marketplace。Agent Skills 标准化会加速分发，也会同步放大 malicious package 的杠杆。

建议：企业 skill registry 必须默认 reject 脚本与外连、最小权限、沙箱执行、签名与 provenance；scanner 只做 triage，不做唯一放行。定期做 source-disjoint 回归和 benign over-flagging 测试。

Grok “Cryptographic Context Injection”：内容分类器看不到的 payload，绕道 Python 工具读取上下文

Adversa AI 向 The Hacker News 披露：恶意网页把加密 JSON、key material 和“解密它”的指令发给 Grok；Grok 在自身 Python execution runtime 解密，再通过 navigation tool 把当前 name、approximate location、subscription tier 和 chat history 放进 URL。公司称 20 次尝试 40% 成功；测试对象是 8/19 的 Grok web chat / Grok 4.5 Fast。当前没有 CVE、没有用户 workaround，也没有公开 xAI 修复。

为什么重要：这不是普通 prompt injection，而是把“让模型亲自执行解密”当成 laundering step。静态 classifier 检查到的是 ciphertext，敏感数据却是 model tool output + navigation 的结果。模型 patch 能挡住内容，也可能堵不住跨 tool dataflow。

必须标注可信度：目前只有研究者一方披露，没有 xAI 复现，成功率也是披露方自报，不能写成已被野外利用。正确做法是把它当高可信架构警告，而不是已证实的 Grok CVE。

💭 深度思考

观点 1：Agent 产品的“源码”正在从 workflow 迁移到 evaluation loop

过去默认的研发流程是：选模型 → 写 system prompt → 接 tool → 看 demo。现在真正拉开差距的是：

  1. 能否从长轨迹提取可迁移、不过期的 subtask skills；
  2. 能否保留证据、发现停滞并及时换路；
  3. 能否用 frontier tasks 做低成本 harness search；
  4. 能否把每次外部动作变成可审计的 policy decision；
  5. 能否在 source-disjoint / hidden set 上证明没有被 evaluation overfit。

主观判断：未来 6–12 个月，agent 团队最该新增的不是更多 agent，而是内部 Agent Evals / Skill Registry / Trajectory Compiler 三个系统。OpenAI、MCP、NVIDIA、arXiv 最近的信号其实是同一件事，只是从不同层切入。

观点 2：小模型真正吃掉的是“昂贵步骤”，不是“智能本身”

今天的 Daedalus、adaptive reasoning 和 Faraday 给出三种不同路线：

  • Daedalus：用 CPU-native 架构吃掉 routing / preprocessing / low-risk local work；
  • adaptive reasoning：让小模型先判断该想多久，把真正昂贵的 reasoning 留给难问题；
  • Faraday：用 27B specialist 掌握 domain judgment，把 coding execution 交给 GPT-5.5 Codex。

结论：“全部用最小模型”不可行；更现实的是把 agent pipeline 拆成 cheap router → specialist reasoner → strong executor → verifier。谁还把整条链绑定在一个 flagship model 上，谁就在为每一次简单分类、重复总结和 schema lookup 支付 frontier 价格。

观点 3：Agent 的下一场安全战争，不在 prompt，而在“内容 → 工具”的边界

MaliciousSkillBench 证明文本扫描很容易 source-overfit；Cryptographic Context Injection 则是另一种极端——内容不可读，但模型通过自带工具把它变成可执行指令。两者合起来说明：

  • scanner 必须与 provenance、sandbox、最小权限、egress policy 叠加；
  • agent identity 与 delegation 要进入 MCP / OAuth / audit log；
  • untrusted content 应在无工具环境先做结构化抽取，privileged context 再消费结果；
  • 对 outbound navigation、payment、publish、merge、shell 等动作，记录解析后的参数与 destination，否则事后看不到到底泄了什么。

主观判断：prompt 防御仍必要，但已是最低一层。生产 agent 的安全单位最终是“带身份的工作负载 + 可执行策略的 harness + 完整 tool trace”，不是一段 system prompt。
