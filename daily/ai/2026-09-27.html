今日头条：Dream-RSI 改写 agent 自我迭代的成本结构

P0 本月最值得关注 Google DeepMind + 马里兰大学 + 弗吉尼亚大学 · arXiv:2609.14858 · 9月15日

一件事：一个 17 人的联合团队（包括 Google DeepMind 核心成员）发了 Dream-RSI: Recursive Self-Improvement through Evolving Worlds。核心思路是——把 agent 跑过的搜索历史变成「replay simulator」，让 agent 在「梦里」测试新的探索策略，几乎零成本评估，再把最优策略部署到真实环境。

数字很关键：在 GEM-Bench 编码任务上，agent 调用从 550 次降到 317 次（5 轮递归），平均运行时间从 3587 ms 降到 2931 ms。某些配置下搜索调用量减少 162 倍。

为什么重要（主编观点）：这是「agent 自我改进」从修辞走向工程范式的拐点。过去 RL/self-play 的成本主要花在「试错」，Dream-RSI 把历史轨迹当沙盒复用，等于把算力成本结构重写了——agent 的迭代不再需要线性烧 token，而是对数级烧。如果这条路径成熟，agent 开发的最优策略不是「训练更大的模型」，而是「积累更厚的轨迹库」。这是 Anthropic / DeepMind / OpenAI 都在悄悄押注的方向。
对你意味着什么：如果你在做 coding agent / research agent，现在就值得把你的 trajectory（每一步决策 + 反馈）持久化、结构化存起来——半年后这就是你的 replay simulator 资产。开源代码已挂在 github.com/zhengkid/Dream-RSI，可以直接跑 demo。

🤖 Agent 前沿

1. CE-Agent：云-端协同的 agent 框架，化解「能力-资源」二难困境

P0 期刊：Journal of Cloud Computing · 9月25日 · Springer 论文

CE-Agent 提出一个自适应进程内卸载路由器（adaptive in-process offloading router）：在多步推理阶段实时评估「token 生成熵」和「本地工具执行错误率」，动态决定这一轮推理放在云端大模型还是端侧小模型跑。

为什么重要：今天 90% 的端侧 agent 架构都是「能跑就跑本地，跑不动就甩云端」的粗粒度二选一。CE-Agent 第一次把卸载决策做成了「per-step」的连续判断——置信度高 / 低熵 → 本地；模型卡壳 / 工具报错 → 云端。这正好踩在端侧 LLM（Muse Glimmer 30B、Gemma 4 12B）爆发的节点上，是「让本地 agent 真能跑生产」的工程拐点。
对你意味着什么：如果你在做端侧 + 云端混合 agent，这篇论文给出了可借鉴的路由器设计模式——entropy + 错误率双信号，不需要额外训练的元模型。可以照着改你的 agent harness。

2. Google CANVAS：把长视频生成当「全局规划问题」而非「prompt 链」

P0 Google Research · 9月25日 · A²RD / VQQA / CANVAS 多智能体框架

Google Research 在 9月25日发布的多智能体框架 CANVAS，把长视频生成看作全局规划而非「prompt by prompt」：用多个 agent 分别管剧本、镜头一致性、人物外貌、配音节奏，再用一个总控 agent 协调，避免「上一帧的脸长到下一帧变成另一个人」的通病。

为什么重要：这是 multi-agent 范式在非文本生成领域的首次工业级落地尝试。文本 agent 我们已经见过太多框架（LangGraph、CrewAI、AutoGen），但多模态、多帧序列的协同规划一直是空白。CANVAS 验证了「agent 编排」可以跨过模态边界。
对你意味着什么：如果你做的是 creative agent / content agent，「全局规划 agent + 专项 agent」的拆分思路比「单 agent + 长 prompt」更稳。先想清楚状态空间维度，再决定要不要上 multi-agent。

3. MCP 协议在 Cursor 上再爆 RCE 漏洞

P1 安全警告 BankInfoSecurity · 9月23日 · 披露

MCPoison 风格的持续性代码执行漏洞再现 Cursor：通过 MCP 协议，恶意 server 可以在用户首次信任之后静默升级为可执行任意命令。

为什么重要（个人观点）：MCP 生态今年累计 CVE 14+ 起，暴露 server 超过 20 万个。Anthropic 推 MCP 时承诺的是「协议即信任」，但事实证明协议本身不能解决信任问题。Agent 开发者必须自己加一层 sandbox + permission gate，不能依赖 MCP 的安全声明。

⚡ 小模型 & 效率革命

5. Liquid AI 发布 LFM2.5-VL-DSpark：vision-language 模型的端侧加速

P0 今日最实用 Liquid AI · 9月25-26日 · 博客

一个 280M 参数的 speculative decoding drafter，专门给 LFM2.5-VL-3B vision-language 模型提速——

  • Apple M5 Max：3.13× 加速（lossless，输出完全一致）
  • H100 GPU：2.66× 加速
  • 只增加 8.9% 显存开销
  • Day-one 支持 llama.cpp / MLX-VLM / SGLang

drafter 只有 4 层 attention、训练 block size 9，专为多模态输入设计。

为什么重要：spec-decoding 不是新东西，但把 drafter 和 vision encoder 联合设计是第一次。以前 VLM 加速都靠降分辨率或砍 vision tower，没人敢碰 decoder。Liquid AI 证明了「多模态场景下 drafter 仍然是金矿」——3.13× 端侧加速意味着手机实时 VLM 不再是 PPT。这是端侧 agent 视觉感知模块的关键拼图。
对你意味着什么：如果你跑 LFM2.5-VL-3B，本周就升级 llama.cpp / MLX，3× 提速白拿。如果你做的是其他 VLM，这套模式可以借鉴——给目标 VLM 单独训一个小 drafter，比通用 speculative decoding 收益高得多。

6. Muse Glimmer 30B：从 Meta 到本地 GPU 的端侧 agentic 旗舰

P1 开源 Meta Superintelligence Labs · 8月10日发布 · Apache 2.0 · HuggingFace

虽然 8 月发的，但仍是本月「端侧 agent」基座模型的代表：30B 参数、Apache 2.0、单 GPU 可跑（24GB 量化版）、原生 DFlash speculative drafter、131K 上下文。在 RTX 5090 上 token 生成快 3.1×，Apple M5 Max 上 1.8×。

主编观点：Meta 在 Llama 4 之后沉默三个月，Muse Glimmer 是「不卷 frontier、改卷 deployability」的转向信号。

7. DeepSeek V4.1 Flash vs Gemini 3.8 Flash：开源 MoE 对闭源 Flash

P1 DeepSeek V4.1 Flash · 9月10日（MIT）· Gemini 3.8 Flash · 9月2日

DeepSeek V4.1 Flash：552B MoE，输入激活 8B、输出激活 16B，MIT 许可证，声称把 agent memory 成本砍到四分之一。

Gemini 3.8 Flash：Google 六周内第三个 Flash 版本，主打 agentic workflow，9月又更新了 antigravity-preview harness。

为什么重要：Flash 级别现在是「开源 MoE vs 闭源优化」的主战场。DeepSeek 用稀疏激活证明「开源也能压成本」，Google 用极致工程化证明「闭源也能打价格」。两端差距在快速收窄，对 agent 开发者是成本下行 + 选择增多的双重利好。

💭 深度思考

洞察 1：9 月下半月在悄悄发生一个范式迁移 —— 从「训更好的模型」到「用更好的轨迹」

三条独立新闻指向同一件事：

  • Dream-RSI 把历史搜索轨迹变成 replay simulator；
  • CE-Agent 把历史 token 熵 + 工具错误率当成路由器信号；
  • LFM2.5-VL-DSpark 把历史 vision token 分布当成 drafter 的训练信号。

三者的共同点是：「数据/历史」本身成为可执行资产。这跟 RLHF 当年把人类反馈变成 reward model 是一个量级的范式信号。

主观判断：未来 6 个月，「trajectory store + replay engine」会成为 agent 中间件的新基类，类似于当年 ORM 之于数据库。建议关注：LangGraph 的 checkpoint store、Letta 的 memory layer、或者直接看 Dream-RSI 的实现。

洞察 2：端侧 agent 的「最后一公里」正在被打通

9 月这三个事情凑在一起很说明问题：

  • Meta Muse Glimmer 30B——30B 跑在 24GB 消费 GPU；
  • LFM2.5-VL-DSpark——VLM 端侧 3.13× 加速；
  • CE-Agent——端云协同路由。

三个拼图凑齐，端侧 agent 终于不再是 demo。如果你做消费级产品，现在可以把 agent 塞进 App / 浏览器插件 / 桌面工具，不需要云端兜底。

行动建议：把 agent 的「最小可端侧化模块」拆出来（通常是一个 7B-30B 的 SLM + 一个 drafter），先跑通 offline fallback，再考虑云端增强。

洞察 3（反向）：被低估的风险 —— MCP 协议信任危机

9月23日 Cursor 的 MCP RCE 不是孤立事件，2026 年累计 MCP CVE 已经 14+。我判断：2027 年 Q1 之前，MCP 会被强制要求「per-server permission + signed manifest」，类似当年 npm 加 integrity hash。

建议：现在就别信任未签名 MCP server 的「首次信任 + 后续静默升级」模型，加一层 own permission gate。
