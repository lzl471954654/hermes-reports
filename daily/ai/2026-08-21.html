💭 深度思考

观点一：2026 下半年「AI 中间层」开始抢走模型厂商的光环。

过去 18 个月，行业的头条都是「某家又发了个更强的模型」。但 8/19–20 这两天最有信息量的事件不是模型——是 Liquid DSpark、Ramp Router、OpenAI ZDR/PSP、Meta Mac App。它们都不是模型，但每一个都在重新定义 agent 工程的边界。当推理加速、模型路由、数据合规、桌面集成都开始作为独立产品存在，「做 agent」的栈就和「做 web 应用」的栈越来越像——底座是几层可替换的中介，上面跑你自己的业务逻辑。

给 agent 开发者的 actionable：重新分配工程预算——把过去押在「选哪个模型」上的时间挪到「搭自己的中间层」。哪怕只是 200 行代码的 router，也比每次手动选模型更值钱。

观点二：端侧 agent 临界点已到——别再假设「必须上云」。

DSpark 把 8B MoE 在 MacBook 上跑出近 3x 加速，Meta Mac App 直接把端侧 LLM 推到「OS 助手」层级。同一天落地的两件事不会是巧合。当端侧 agent 既够快、又能看见用户屏幕时，「数据不上云」从合规诉求变成了产品卖点。医疗、法律、企业内部数据类 agent 会在 2026 Q4 出现一波明确的产品化迁移。

给 agent 开发者的 actionable：在你的下一个项目里，把「能不能完全跑在用户设备上」当作一个独立的设计维度来评估。Llama.cpp + GGUF + DSpark 这条栈今天就能跑起来——值得花一个周末做技术验证。

观点三：研究界已经在悄悄给「thinking 更久 ≠ 更好」盖章。

虽然不在今天头条里，但 arxiv 2604.10739 / 2604.14853 这两篇 4 月的 paper 在 8 月频繁被引用：长 CoT 边际效用递减、test-time compute 应该按 query 难度自适应分配。换句话说，o1-style 「无限 thinking」 不是免费午餐——复杂问题才值得烧算力。

给 agent 开发者的 actionable：在 agent 编排里加一层「是否进入深度推理模式」的判定器。简单分类、抽取、格式化任务完全不需要 reasoning 模型；研究、规划、数学证明才需要。Ramp Router 的 40% 节省里，相当一部分来自这种「按需启用 reasoning」。
