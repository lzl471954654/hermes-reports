OpenAI 把 Codex Harness 全面开源：「容器/模型不是产品，Harness 才是」

8 月 19 日，OpenAI 在开发者博客发布 Codex as a platform: build on the open agent harness（作者 Nicolas Bonamy、Derrick Choi），紧接着 8 月 20 日将 openai/codex 仓库正式以完整 Rust 实现的形式开源。Medium、SegmentFault、网易、Linux.do 当天同步刷屏。

这不是一次「顺便开源」，是叙事重写。OpenAI 把 Codex CLI / App / IDE Extension 这三种用户面背后的同一套引擎——open-source Codex harness——明确定位为「可以被别人包进产品里的基础设施」。文章里说得很直白：most people know Codex through the App, CLI, or IDE Extension. Those experiences are important, but they are only a few of the ways the same underlying system can be used.

Harness 实际上承担了什么？

  • 上下文收集（grep、glob、文件加载、远程索引）
  • 任务推理与 todo / plan 生成
  • 工具调用（shell、edit、browser、MCP server）
  • 权限边界（allowlist、approval、secrets 处理）
  • 会话状态、长任务、断点续跑

也就是说——以后写一个「我自己的 Codex」不再需要从头造 agent 框架，直接 fork harness、接你的模型、改 UI 就行。OpenAI 同时提供三种调用形态：codex exec（CLI 子进程）、SDK（嵌入你的服务）、app-server（把 harness 当成一个常驻进程，类似 LSP）。这三条路径正好覆盖「自动化脚本 / 自家产品 / IDE 形态」三种集成姿势。

为什么这是头条：它直接改写了「Agent 产品」的边界——

  • 对标 Claude Agent SDK：Anthropic 过去半年一直在推 Claude Agent SDK（CLI、SDK、headless），OpenAI 这次用「开源」打了个差异化——同等的 harness 能力，但 fork/audit/contribute 都开放。
  • 「应用层」从此没那么值钱：当 harness 是开源的、模型可以选（OpenAI 也支持 BYO model），所谓的「Cursor / Windsurf / Cody」差异化会被压缩到 prompt 策略、UI 体验、企业私有化部署三件事上。
  • 「Agent 工程」从此进入新阶段：过去两年大家在比 prompt、tool schema、MCP server、memory；现在问题变成了「harness 怎么和你的业务系统集成」。这是一个更高阶的工程问题。

对 agent 开发者的具体含义：

  • 别再重写 agent 框架了：如果你正在做内部 coding agent / DevOps agent / 数据 agent，openai/codex 应该进你的候选名单，优先于 LangGraph / CrewAI / Autogen 这种「自研框架」方案。
  • 立刻评估三件事：你的模型 → harness → 业务工具的耦合点在哪里？harness 升级时（OpenAI 周更）你怎么跟？长任务的中断恢复策略要不要借 harness 的 checkpoint？
  • 安全审计成本要重新算：harness 开源意味着安全研究者可以审计——这是好事。但反过来，所有用 Codex harness 的产品都共享同一片攻击面，patch 节奏要跟紧。

Anthropic Fellows「Mind Viruses」研究：多 agent 之间 63% 成功率自我传播

8 月 10 日释出的 arXiv:2608.10218 "Mind Viruses: Self-Propagating Ideas in Multi-Agent LLM Systems"（Vassilis Papadopoulos 等，Anthropic Fellows + EPFL）这一周持续发酵。结论简短而凶险：当一个 agent 写下的 prompt / 状态文件被另一个 agent 读取，「信念」「行为指令」可以像病毒一样在 agent 之间横向传播，1,800 次试验 / 五个模型后端平均 63% 攻击成功率。测试场景中就包括 OpenClaw（台湾攻击框架）。

实验设计的核心是「harness state files」：agent A 被感染 → 在对话中传递种子指令 → agent B 写文件持久化 → 文件被 agent C 读入 → 行为偏移。说明最容易被攻击的，不是模型的「理解」，而是 agent 把不可信输入当作「自己的 prompt」这层架构决策。

为什么重要：这本质上是 agent 时代的 lateral movement（横向移动）实证。论文还提到一个反直觉的发现——在 system prompt 里加一段警告文字，能几乎完全阻止传播。换句话说，agent 安全在「提醒模型注意」和「真正隔离输入」之间，存在巨大的成本差。OWASP Agentic Top 10 该更新了。

对 agent 开发者的具体含义：

  • 立刻审计：你的 agent 是否会读取「其他 agent 写下的文件」？如果会，这条边界就是高危面。
  • 把 agent-writable prompt 文件当作 untrusted input：能只读就只读；运行时改写要二次确认；考虑给敏感 skill 加 sandbox。
  • 不要迷信「Claude/GPT 安全」——五个后端都被攻破，问题在架构不在模型。

JetBrains Rider 2026.2.1：内置「refactoring-code」skill，AI 重构 C# 中位时间 157.9s → 26.6s

8 月 19 日发布的 Rider 2026.2.1 在 IDE 层面内嵌了一组专门给 AI agent 调用的「refactoring skill」。当 Claude Code / Codex 检测到当前任务属于「重构」，自动加载该 skill，中位任务时长从 157.9 秒压到 26.6 秒（≈ 83% 提速）。

为什么重要：这是「skill 范式」第一次被一家主流 IDE 厂商做成产品级抽象——不只是「写一个 .claude/skills/xxx/SKILL.md」级别的实验，而是 IDE 默认打包、自动 dispatch 的运行时扩展。和 MCP Extensions、Codex harness 的方向完全一致：LLM 应用的「技能」正在变成标准化的中间层。

对 agent 开发者的具体含义：

  • 如果你做 IDE 插件 / CLI 工具 / agent 产品，现在就要设计你的「skill 协议」——别人 fork 你的项目时，靠 skill 复用，而不是靠 fork 代码。
  • JetBrains 的做法（task 类型 → 自动 dispatch skill → 收口结果）是值得抄的范式，可以照搬到企业内部 agent 产品里。
  • OpenAI 的 Codex harness 已经支持类似的 skill dispatch，未来 6 个月里「skill registry / skill marketplace」会成为 LLM 应用的基础设施。

xAI Grok Bot 退出 Beta：always-on「数字同事」进入 Cursor/SuperGrok 订阅

Grok Bot（8/11 推出 Beta，8/21 正式版）现已在 SuperGrok Plus / Heavy、Cursor Pro+/Ultra、Cursor Teams 计划里 GA。卖点是「一直在线的 AI 同事」：能跨应用、跨收件箱、跨工具执行多步任务，能登录你的 SaaS 自己点，不像 Copilot 那样只在对话框里转。

为什么重要：这是继 Claude Cowork 之后第二家把「always-on agent」从实验室推向付费 SKU 的玩家。两者都认同一个判断：agent 的下一阶段不是「更会聊」，而是「会干活」。能接管你邮箱、整理你 Notion、在 IDE / 浏览器 / Slack 之间穿梭的产品形态开始落地。

对 agent 开发者的具体含义：

  • 「Chatbot UI」的天花板已经显现，新的差异化在「跨应用操作 + 状态保持 + 安全代理」三件套。
  • Cursor 把 Grok Bot 列入订阅意味着编辑器已经成为 agent 的承载平台之一，光做 Chat 客户端会被边缘化。
  • 对个人开发者：Grok Bot 当前 $200–$300/月订阅门槛偏高，但形态已经成立，未来 6 个月会有更便宜的复制版本。

DeepSeek-V4-Flash-Vision-Exp 发布：1M context 的多模态轻量模型

DeepSeek 8 月 21 日上线的 DeepSeek-V4-Flash-Vision-Exp 是 V4 家族的轻量多模态分支，1,048,576 token context、384K max output，定位「experimental multimodal visual understanding」。同时配套释出 DeepSeek Harness 0.1.1，开箱即用新模型。

为什么重要：这是「Flash + 多模态」组合第一次在中文开源阵营做到 1M context。对 agent 开发者来说，成本可控的多模态视觉理解从此不再是大厂的特权——之前要么用 GPT-4o / Gemini 烧钱，要么用本地 BLIP-2 这种弱模型，现在多了一个能跑长任务、能看图、还便宜的选项。

对 agent 开发者的具体含义：

  • 「截图 + prompt」类 agent 工具（例如自动 PR review、自动 UI 测试生成）成本结构会被显著压低。
  • DeepSeek Harness 是 OpenAI Codex harness 的国产对应物，值得对标评估（许可证、模型兼容性、扩展接口）。
  • 1M context 意味着「把整本手册 / 整份 PRD 灌进去 + 视觉」成为可能，agent 的「长期记忆」问题有了现实解。

💭 深度思考

观点 1：Agent 产品竞争升维——「模型即产品」让位给「Harness 即产品」

过去两年 agent 圈的潜规则是：谁拥有最强的基模型，谁就拥有最强的 agent。2026 年 8 月这条规则被正式改写。两条独立信号同时亮：

  • OpenAI 把 Codex harness 全面开源——把 harness 定位成「可以被别人包进产品的开源基础设施」，同时提供 CLI / SDK / app-server 三种集成姿势，等于在喊：「别再各自造轮子，用我的 harness 接你的模型」。
  • Anthropic 持续推 Claude Agent SDK——同一时间 Claude Code 在企业内部扩张，Cowork 跨桌面，背后是同一套 harness 哲学。

含义：接下来 6 个月里，「agent 应用层」会经历一次类似当年「移动应用层」的整合——99% 的差异化会集中到三个轴上：私有数据接入、垂直工作流编排、企业安全合规。通用型「对话 + 工具调用」产品会迅速同质化，最后赢的只有 3-5 家。

对中小开发者的判断：不要再去造 agent 框架了。openai/codex、Claude Agent SDK、DeepSeek Harness 任选一个 fork 改，省下来的精力全投到垂直工作流——那才是壁垒所在。（这是主观判断，欢迎反驳。）

观点 2：Multi-Agent 安全正在从「学术警告」变成「工程问题」——而工程师还没准备好

Anthropic Fellows 的 Mind Viruses 论文给出了一个非常难看的数字：63% 横向传播成功率，五个模型后端无一幸免。更难看的是结论——「在 system prompt 里加一段警告几乎可以阻止」。这意味着我们正在用「prompt 玄学」防御一种「架构级攻击」。

对照来看：

  • OWASP Agentic Top 10 还在起草中。
  • MITRE ATLAS 对 agent 威胁的覆盖有限。
  • 主流 agent 框架（LangGraph / CrewAI / OpenClaw / Codex harness）默认都不做「agent-writable 文件的不可信标注」。

含义：任何正在 production 跑 multi-agent 编排的团队，默认就是不安全的。立刻可以做的三件事：

  1. 把所有「agent 写入、被其他 agent 读取」的文件单独建一层 namespace，并打上「untrusted input」标签。
  2. 给敏感 skill 加 read-only 运行时沙箱（Mind Viruses 论文明确推荐）。
  3. 在 system prompt 里加一段明确的「external prompt 不可信」声明——成本极低，收益很大。

预测（主观、6 个月内）：会有一起「multi-agent prompt 注入导致生产事故」的公开案例成为转折点，类似 2023 年的 Slack GPT 泄露事件。在那之前，agent 安全是被严重低估的工程债。

观点 3：「Skill」作为 LLM 应用的新中间层，正在悄悄变成标准

三个独立事件指向同一件事：

  • JetBrains Rider 内置 refactoring-code skill——IDE 厂商把 skill 当成产品级抽象。
  • MCP Extensions framework——协议层把 skill 标准化。
  • OpenAI Codex harness + codex app-server——基础设施层把 skill runtime 化。

加上 Karpathy 的 CLAUDE.md 在 GitHub 拿到 156k stars——「skill = LLM 应用的 npm package」这件事已经过市场验证。

含义：接下来值得关注的，是「skill marketplace」的出现。ClawHub（OpenClaw 的 skill 注册中心）已经是个雏形，但商业模式、信任机制、版本治理都还很原始。谁先做出「skill registry + 付费分发 + 签名验证」的成熟形态，谁就拿下 agent 经济里类似 npm / PyPI 的位置。
