🤖 Agent 前沿

P0-1 · Anthropic Claude Haiku 5.5 —— 1M context + adaptive thinking 把"小模型"重新定价

P0 10/7 小模型 前沿厂 LLM Releases · Anthropic timeline

发生了什么：10/7 Anthropic 发布 Claude Haiku 5.5，接替 Haiku 4.5。三个关键参数：

  • 1M token context —— Haiku 系列第一次拿到 1M，是 Sonnet/Opus 档位下沉；
  • Adaptive thinking 开箱即用（默认 effort = medium，用户可调 low/medium/high/xhigh），是 Haiku 系列第一次支持 effort 控制 —— 比 Sonnet 5.5 的 effort 控制更精细；
  • 价格"最便宜"：Anthropic 公开声称是"最便宜最快的小模型"，比 Haiku 4.5 降 90%（业界引用的折扣档位）。

为什么这件事比"又发一个 Haiku"重要得多：

  • 第一，context 长度不再是档位指标，而是模型门槛。2024 年 1M 是 frontier 旗舰的卖点，2025 年 Sonnet 把它拉到中端，2026 Q4 Haiku 把它拉到小端。这意味着 "agent 的上下文预算" 在 2027 年会继续扩张，长 prompt / 长 tool result / 长 conversation history 不再是设计约束；
  • 第二，effort 控制在模型内建出现，意味着可以"快路径走 low effort、慢路径走 high effort"，agent 调度从"调用不同模型"变成"同一模型不同 effort"。这个抽象级别上升省掉了多 model provider 路由；
  • 第三，90% 价格降幅是 agent 商业模式的重置。一个典型 multi-agent 系统（如 Claude Sonnet 5.5 1000-agent workflow 被 10/10 那批报道提及）每条消息 0.5-2 美元跑 1000 agent —— 切到 Haiku 5.5 等价能力下成本下行 1 个数量级，很多"agent 太贵"的早期产品判死刑。
对 agent 开发者的实际意义：先做的两件事：(1) 把 agent 里"长上下文但不需要深推理"的子任务（文件摄取、grep-style 召回、长 evidence collection）切到 Haiku 5.5，成本立刻 5-10x 下降；(2) 把 multi-agent 里"协调者 agent"的 role 切到 high effort、"工人 agent"的 role 切到 low effort，runtime 内简单 effort 路由即可，不需要两套 model API。

P0-2 · Anthropic "Agent View" —— multi-agent 编排第一次成为可观测的一等公民

P0 本周 multi-agent orchestration 前沿厂 LinkedIn 报道

发生了什么：Anthropic 上线 Agent View —— 把 multi-agent 内部编排（哪些 agent 在跑、他们之间说了什么、谁调用了谁、每条 tool call 的成本/延迟）以 可视化 timeline 形式暴露给开发者。这是 Anthropic 给 Sonnet/Opus 5.5 上的 1000-agent workflow 提供"官方可观测性"的第一步。

为什么重要：

  • 第一，从 LangGraph / CrewAI / AutoGen 时代开始，"agent 编排不可观测"就是头部痛点。你只能看到最终输出，看到不了一个 5-step planner 里哪一步被 retry 3 次、哪一步 cost 90% 的 token、tool call 是不是死循环。Agent View 解决了这件事；
  • 第二，VisionBinder AI 等第三方也在做"合规版"agent 编排可观测性（来自同期 LinkedIn 文章），说明这条赛道已经被验证，Anthropic 自己也下场意味着 agent 编排可观测性从"best practice"升级成"vendor 默认"；
  • 第三，可观测性是 enterprise sales 的硬门票。"agent 给客户跑但跑的过程你看不了"在 2025 年还能勉强卖，2026 H2 开始 enterprise procurement 要求 step-level 审计，Agent View 是 Anthropic 抢这张门票的明确动作。
对 agent 开发者的实际意义：用 Claude Sonnet 5.5/Opus 5.5 做多 agent 编排的，本周就去打开 Agent View。至少 3 件事可以立刻做：(1) 把"哪个 agent retry 最多"作为成本异常信号；(2) 把"tool call deadlock 模式"作为 prod alert；(3) 把"agent-token / task-token"比率记到 SLO，自己 agent 的"经济账"就跟基础设施一样可管了。

P0-4 · Adaptive Theory of Mind (A-ToM) —— AAAI 2026 把 "agent 间心智建模"做成可在线优化

P0 AAAI 2026 paper multi-agent A-ToM 笔记

发生了什么：AAAI 2026 接收的 multi-agent 协调论文 A-ToM (Adaptive Theory of Mind for LLM-based Multi-Agent Coordination) 把"对其它 agent 心智建模"这件事从离线训练做成在线 expert advice 框架：agent 之间实时相互建模，按"在线 ToM order alignment"决定下一步行动。

为什么重要：

  • 第一，过去 multi-agent LLM 系统的 reasoning 范式是"显式 prompt 里写：'agent A 在想 X'"，慢且脆。A-ToM 把 ToM 建模和推理对齐在在线梯度层做，不污染 prompt；
  • 第二，arXiv 上 2609.35928 "Prompted Identity Degrades Cooperation in Multi-Agent LLM Systems" 这篇 9 月底挂的论文发现一个反直觉结论：告诉 agent 对方"是什么模型"反而让合作质量下降（GPT-4o 跟 Claude 互知身份时表现不如匿名）。A-ToM 的"ToM order alignment"正好回应了这个负面结论 —— "建模对方但不让对方知道你知道"；
  • 第三，从工程角度看，A-ToM 给出的"在线 expert advice"框架可以装到任何 LangGraph / CrewAI 流水线里，不依赖新框架。这是论文能与生产管线耦合的关键。
对 agent 开发者的实际意义：上周我们读 2609.35928 论文时已经发现"agent 之间互知身份 = 合作质量下降"，A-ToM 是对症药。如果你的 multi-agent 系统里混了 Claude + Qwen + DeepSeek + Mistral，做 A/B：把"告知对方模型身份"的 system prompt 段去掉，大概率合作完成度上升 5-15%。这是一周内能做的实验。

对 agent 开发者的实际意义：(1) 立即审查你的 agent 是否给了 shell / filesystem write 权限，如果是生产环境，把 self-replication 路径封掉（rate-limit on spawn + per-process filesystem scope）。(2) 立即审查你的训练数据来源，如果你 2025-2026 训练或微调时用了 Claude/GPT API 调用，上游被认定"蒸馏源"的训练数据有合规污点风险，需要做 audit log 留存至少 12 个月。

P0-6 · DeepSeek-V4.1-Flash —— "scaled-down 旗舰" 路线固定，把 frontier 工厂切成天级

P0 本周 小模型 中国模型 开源 DeepSeek 官方

为什么这件事比"再发一个小模型"更重要：

  • 第一，DeepSeek 走的是"切片发版"：同一个底层架构（V4.1）每周/每两周出一个新 snapshot。好处：用户在同价位下默认拿到当下最强；代价：开发侧要做 version pin + 校验和锁。

  • 第三，"native 视觉理解"写在 Flash 上。多模态下沉到 Flash 档，意味着 Vision-Language Agent 的成本可以跟纯文本 Agent 拉平 —— 这是 Z.ai CogAgent-9B 的同方向动作，中国厂把"开源多模态小模型"做成了完整梯队。
对 agent 开发者的实际意义：把 DeepSeek-V4.1-Flash 当 "agent 主力 fallback 模型"，搭配 Claude Haiku 5.5 做主路径。两个事实：(1) 它是开源可 self-host，企业/合规路径首选；(2) 当前 snapshot 编号在变，要做模型版本校验和验证，不要锁 alias 名（要锁 snapshot commit hash / SHA256）。

P0-7 · EmbeddingGemma 2 —— 740M Apache 2.0 多模态 embedding，"agent 检索"成本结构再被压一层

P0 10/6 公告 效率 开源 Apache 2.0 前沿厂 EmbeddingGemma 2 详解

发生了什么：Google DeepMind 在 10/6 公告 EmbeddingGemma 2（同日 Hugging Face 上线 weights）—— 740M 参数 Apache 2.0 多模态 embedding 模型，文本/代码/图像/视频/音频统一映射到 768 维向量，8K context，Matryoshka Representation Loss（向量维度可裁剪）。

为什么重要：

  • 第一，"统一 embedding 空间"是 RAG 长期难题 —— 文本和图像在同一个 retrieval space 才能做"图问文答、文找图、音频找视频"这类跨模态 agent 任务。EmbeddingGemma 2 用 740M 把这件事做下来，比之前的多模态 retrieval pipeline（CLIP + text embedder）少一个 model hop；
  • 第二，Matryoshka 是它的工程亮点：在 768 / 512 / 256 / 128 维下都能保持 retention（精度下降有限）。这意味着存储成本可以动态调节，100M 向量的索引从 768 维 250GB 降到 128 维 42GB，在端侧/边缘/小团队部署上是真实红利；
  • 第三，Apache 2.0。这跟 OpenAI / Cohere 的商用 embedding API 比是显著差异 ——任何商业产品可以免费 self-host，把"向量检索这一层"从 monthly API fee 切到一次性硬件成本。
对 agent 开发者的实际意义：(1) 如果你的 RAG / vector search 还在用 OpenAI text-embedding-3-small，把 EmbeddingGemma 2 当成 90% 降本替代（保留 API 用作精度对照）；(2) Matryoshka 维度可裁剪让你可以给"热的"chunk 用 768，"冷的"用 128，同一索引混维度，存储直接减半。

P1-4 · "Prompted Identity Degrades Cooperation" arXiv:2609.35928 —— agent 互知身份的负反馈

P1 paper multi-agent paperswithcode

论文证实：当 multi-agent 系统告知每个 agent 对方"是什么模型"（GPT-4o / Claude / Qwen）时，合作质量会显著下降 —— 出现"模型家族聚类"，agent 偏向跟"同家族"合作。看点：multi-agent 系统里把"模型身份"从 prompt 里隐去是个低成本高收益动作（与 P0-4 的 A-ToM 论文呼应）。

P1-5 · Agent-Reach (Panniantong) —— 87.8k stars，agent 数据采集"绕过 API"的默认栈

P1 开源 agent 工具 Panniantong/Agent-Reach

Agent-Reach 让 agent 用一行命令统一访问 Twitter / Reddit / YouTube / GitHub / Bilibili / 小红书等 16 个平台，零 API 费。看点：搜 Wikipedia / 平台 anti-bot 已经升级，调研类 agent 的"主链路"应该切换到 hosted API（Tavily / Exa / Brave），Agent-Reach 仅做 fallback。

P1-6 · DarkForest (arXiv:2605.25188) —— "less talk, higher accuracy" multi-agent 范式

P1 paper multi-agent HuggingFace papers

论文主张 multi-agent 系统"少说多做"：减少 agent 间冗长对话、让每个 agent 直接产结构化输出、再做 aggregation。看点：很多 multi-agent 系统 token 80% 浪费在 agent 间寒暄上，DarkForest 的思路能省 30-50% token。

P1-7 · NASA-ESA "Mind Viruses" arXiv:2608.10218（Jack Lindsey / Anthropic）

P1 paper 安全 论文解读

Anthropic Transformer Circuits 的 Jack Lindsey 把"自传播 idea"在 multi-agent 系统里的扩散建模为"认知病毒"。论文指出：特定 prompt 构造可以让一个 idea 在 100-agent swarm 里 80% 的 agent 一致持有该 idea。看点：agent 治理 / prompt 注入防御的新基线。

P1-8 · China Telecom "Xing4.0-29B-A4B"（OpenRouter 已列）—— 国资 MoE 加入 frontier 队列

P1 中国模型 OpenRouter models

中国电信 AI 团队 (TeleAI) 把 TeleChat 系列的下一代 Xing4.0-29B-A4B（29B-A4B 是 active params = 4B 的 MoE 配置）放到 OpenRouter。看点：国资系 / 央国企 frontier 实验室也开始按月发版，OpenRouter 的"非美国厂 frontier"占比在上升。

💭 深度思考

观点 1：2026 Q4 是 "档位反转" 起点 —— Haiku 5.5 让"小模型"不再是 fallback

这周最被低估的事件是 Haiku 5.5 的 1M context。表面上是发新模型，本质是档位系统重排：

  • 2024：1M context = frontier 旗舰卖点；
  • 2025：1M context = Sonnet 中端；
  • 2026 Q4：1M context = Haiku 小端；

下一站：2027 H1 我们大概率会看到 Haiku 5.5 有 reasoning effort control 同时支持 fine-tuning（Anthropic 已经支持 Sonnet 自定义），那时候"主流 agent 负载 80% 跑 Haiku"会成为默认架构（剩下 20% Sonnet/Opus 才走 frontier）。

对 agent 团队的事：本周就是重新审视"为什么我的 agent 用了 Sonnet/Opus"的时刻。绝大多数用例切到 Haiku 5.5 + adaptive effort 就能保持质量 + 大幅降本。

观点 2：frontier 厂集体"闭源化" —— Meta + Google + Anthropic 路径收敛

把过去三周的事并排放：

  • Meta Muse Wonder 闭源（10/12）—— 此前 Llama 3 一直开源；
  • Google Gemini 4 Argon 闭源 + 限时 intro 价（10/13）—— 跟 OpenAI o-series 同款；
  • Anthropic Sonnet 5.5 / Opus 5.5 持续闭源；
  • 留出 Mistral Le Chonk（10 月底 open-weight 承诺）、DeepSeek、智谱、阿里 Qwen3.x 等少数开源路径。

这意味着 2026 Q4 到 2027 H1 的开源 frontier 进入"中美欧"小联赛，美国 frontier 全部闭源，欧洲 Mistral 是唯一定位"open-weight frontier"，中国 DeepSeek/Z.ai/Qwen 是"分布式开源 frontier"。对 agent 开发者：想自托管 / 想监管友好 / 想防 vendor lock-in 的 agent 产品，开源侧的选择会变窄但更值得长期投入（押 Le Chonk + DeepSeek V4.x + Qwen3.x + GLM 5.x 这四家）。

观点 3：MIT 把"agent"命名成时代词 —— 这是 2026 H2 监管窗口期的前奏

MIT AI Conference 用 "Age of Agency" 命名，学术界 + 政策界的双重背书已经在 10/17-10/19 完成。叠加 Anthropic 10/13 self-replicating AI 警告，2026 12 月-2027 3 月极可能看到：

  • EU AI Act 第二次 amendment 进入"agent 自主性"条款；
  • 美国 EO 14110（2023 Biden 那个）被后续 EO 替换，明确"agent capability tiers + mandatory audit"；
  • 中国生成式 AI 服务管理办法第二次修订加入"self-replicating AI"红线。

对 agent 团队的事：从现在起，agent audit log / agent decision trace / agent cost attribution 三个数据流进你们数据栈的优先级拉满。一年后这些日志就是合规金标准。
