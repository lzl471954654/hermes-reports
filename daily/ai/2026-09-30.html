一件事：昨天的 OpenAI DevDay 2026 不是一次「发布新模型」——而是把 agent 产品化（Dots）、模型价格（GPT-6.1 Sol）、推理速度（Ultrafast）、订阅上限（Pro 500）、开发工具（Agents API + Codex Cloud）五条战线一起推进。在 agent 这条主线上，OpenAI 的姿态已经从「提供模型让别人做 agent」转向「agent 是云平台的新 primitive」，这是 Anthropic 的 Claude Code + Cowork 走通的剧本，OpenAI 用标准化 API + SDK + Console 三件套把它规模化。

为什么重要（主编观点）：把五条战线拆开看，每一条都「还行」；但合在一起看是一次对全栈生态位的饱和攻击。「1/5 价格的 near-Astra 模型」+「always-on agent 平台」+「8× 速度档」三个变量同时调，竞争对手很难在任何一个维度上单独防守。具体含义：a) Anthropic 必须降价或出性能更优的小模型，否则 Sonnet 5.5 这类「次旗舰」会被 Sol 在性价比上吃掉；b) Meta 的 Muse 必须在 always-on + 4,000 app 之外找到差异化（目前它 22 天下载 3M，但前两天刚出隐私泄露）；c) Google 还没出「always-on personal agent」对位——Gemini Enterprise 有 Live Avatar 但没有 Dots 这种形态，这是 Gemini 4 之前 Google 最大的产品缺口。
对你意味着什么：① 本周内把你的 agent 成本模型重算一遍——如果之前用 GPT-6 Astra，迁移到 GPT-6.1 Sol 后同样的 token 量直接砍 80%，但要看 Sol 的真实 computer-use / multi-step workflow 表现再决定。② Agents API 进入 beta 意味着「OpenAI-hosted agent runtime」已经可生产化，如果你还在自建 LangGraph runtime 做长程任务，今天开始 review Agents API 的 beta 是否能覆盖你的 80% 场景。③ Codex Cloud + 自动 security scan 让 GitHub PR review 工作流从「cursor + sonnet」变成「Codex cloud + 自带 scan」，中大型 team 应立即评估是否取代部分人工 review。

🤖 Agent 前沿

1. Dots — OpenAI 把「always-on agent」产品化，每个 agent 配独立云电脑 + 浏览器

P0 DevDay 主角 OpenAI · 9月29日 · 官方介绍 · WIRED 深度 · ChatGPT Learn 文档

Dots 是 OpenAI 首个面向 C 端消费者的「always-on agent」产品形态——每个 dot 基于 GPT-6 Astra 跑，每个都有独立的云电脑 + browser 实例，连接约 4,000 个 app。视觉上是一坨「可以个性化」的 blob，分配给它「多步骤项目」它能持续在后台跑。可通过 ChatGPT 消息入口交互，目前只在 Pro 200 / Business Premium 提供，Engadget 提到用户可同时控制多个 dot。

为什么重要：always-on agent 不是技术问题（技术上 Manus / Devin / Claude Cowork 都跑过类似形态），问题是 谁来提供 sandbox、状态、token 经济。Dots 的真正突破是 OpenAI 把这三件事打包成「产品」对外卖——agent runtime 第一次有了 ChatGPT 这个消费级入口。Meta Muse 上线 22 天下载 3M，已经验证了 consumer 端的 always-on agent 有真实需求；Dots 把同样的需求用 ChatGPT 的流量入口吃下来，竞争格局从「5 家 agent 创业公司」变成「5 家巨头争 always-on 这个坑位」。
对你意味着什么：① 如果在做 B 端 agent，把「always-on + 跨 app」当成你 pitch 的核心能力——巨头会吃掉 C 端长尾，B 端的专业 workflow（法务 / 医疗 / 财务）是它们的盲区。② Dots 用了 Pro 200 起跳，意味着 OpenAI 也在承认「持续后台 agent」是高 ARPU 产品，可以重新校准你自己的 SaaS 定价。③ 注意 Dots 强调的「specialist dots for organizations」+ 与 Microsoft Agent 365 集成——这是 ToB 的入口信号，B 端 isv 应该开始接 Microsoft Agent 365，它会变成 OpenAI 在企业的分发渠道。

2. Shopify 把 WebMCP 推进到 checkout — 浏览器 agent 第一次可以「替人下单」

P0 9月28日 Shopify · Gil Greenberg (Staff PM) · 官方 changelog · TechCrunch · 实测报告

Shopify 在 9月28日把 WebMCP 支持从 storefront 扩到 checkout，新增 4 个工具：get_checkout / update_checkout / complete_checkout / navigate_to_storefront。浏览器 agent 现在可以读 checkout、修改、提交订单——但 3D Secure / blocking UI extension 仍强制交还人工。Shopify 自家测试：agent 任务完成速度 2.7×、成本 58%↓。同时 The Paypers 提到 Amazon 已经把 Meta Muse 屏蔽在 amazon.com 之外——零售平台的 agent 接入策略开始分化。

为什么重要：这是 「agent 替人花钱」这件事第一次有了工业级落地点。checkout 之前是所有 AI 项目的雷区——支付、风控、KYC 都被人工接管；Shopify 把「agent 能做的部分」标准化为 4 个 WebMCP 工具，同时把「必须人工接管的部分」明确边界，这是 agentic commerce 的参考实现模板。Amazon 的反向操作说明：商户平台在用「主动屏蔽 vs 主动接入」划分两个阵营——Shopify / Stripe 是「主动接入」，Amazon / Walmart 是「主动屏蔽」。未来 12 个月这两派的边界会决定 agentic commerce 的格局。
对你意味着什么：① 如果做电商相关 agent，立即去看 Shopify WebMCP 的 4 个工具签名——它是当前最标准的 agentic commerce 接口，会被其他平台 copy。② 把「必须人工授权的 step」当成你的 design constraint：3D Secure、收货地址改写、超过 X 美元的订单——把这些标成「agent boundary」是合规与 UX 的双优解。③ Amazon 屏蔽 Muse 这件事意味着「agent 跨平台操作」不是开放 API，是平台级政治——做跨平台 agent 要准备好「有些平台会直接 ban 你的 agent 指纹」。

3. Agents API 进入 public beta — OpenAI 把「hosted multi-agent + computer use」打包成云服务

P0 DevDay 主菜 OpenAI · 9月29日 · Agents API 介绍（9月10日） · DevDay 公告汇总 · 社区资源帖

Agents API 在 DevDay 2026 升级：hosted execution、memory、tools、multi-agent support、context compaction，并正式支持 computer use（让 agent 操作浏览器 / 软件完成任务）。它把 Codex 的 multi-agent loop、tool search、tool calling、context compaction 这套 runtime 暴露给第三方开发者。

为什么重要：这是「云平台 agent runtime」第一次有了和「自建 LangGraph / CrewAI」正面 PK 的产品形态。过去 12 个月所有 agent 框架都赌「自建 runtime 更灵活」；OpenAI 用 hosted execution 把灵活性的代价（state 管理、sandbox、长期 session、context compaction）一次性外包掉。如果你的 agent 不依赖太多私有中间件，把 runtime 交给 OpenAI 是合理的。如果你的 agent 需要高度自定义的中间件（私有 vector store、私有 evaluator），则需要继续自建。
对你意味着什么：① 本周内完成一份「Agents API 覆盖度矩阵」——把你现有 agent 的 10 个核心能力画在表上，看 Agents API 哪些能直接 cover，哪些需要 fallback 到自建。② Computer use 进入 beta 意味着「浏览器自动化 agent」的开箱即用能力又上了一个台阶——之前依赖 Browserbase / Steel / Skyvern 的项目需要重新评估。③ Context compaction 暴露出来是一个被低估的能力——长程 agent 的内存成本问题第一次有云端原生解，可以极大简化你现在的「截断 + 摘要 + 重读」三件套。

4. Codex Cloud + 自动 security scan — coding agent 走出「IDE 内的玩具」

P0 DevDay 当日 OpenAI · 9月29日 · TechCrunch · the-decoder

Codex 现在有了 可复用的云端开发环境（reusable cloud environments），跨设备访问。GitHub 仓库层面加了自动 security scan。Codex 桌面 app 里加了 code review 视图。Plugin extensions（side panels / interactive panels / file browsing）在 ChatGPT 和 Codex 内启用，Figma 和 Adobe 演示了集成。

为什么重要：Codex Cloud 把「开发环境」这个 GitHub Codespaces / Gitpod 一直在做的事，变成 agent-native 的形态——环境是 agent 持续存在的载体，不是开发者临时起的容器。这条路 Anthropic 的 Claude Code 在 desktop 走了一半（CLAUDE.md / skills 持久化），OpenAI 把另一半（跨设备云端环境）补齐。Coding agent 的「harness 持久化」战争已经分出胜负——是云端托管，不是本地 daemon。自动 security scan 意味着 OpenAI 试图把 agent 从「写代码」拓展到「管代码安全」，这是吞并 Snyk / Sonar 类工具的信号。
对你意味着什么：① Codex Cloud 跨设备的体验直接对标 Claude Code + Cowork——如果你现在用 Claude Code 做主力，可以分一部分日常 dev task 过去对比。② 自动 security scan 这种「agent 自动审计代码」能力会很快成为 PR review 的标配，做 code review 工具的团队需要关注。③ Plugin extensions 让 Figma / Adobe 直接进 ChatGPT——设计师工作流的 agent 化要来了，如果团队里有 design-to-code 自动化需求，这是新的入口。

5. Claude Sonnet 5.5 — Terminal-Bench 4.0 上 70.6%，价格不变

P1 Anthropic · 9月28日 · Artificial Analysis · MarkTechPost · OpenRouter API

Claude Sonnet 5.5（Claude 5.5 系列第二款，紧跟 Opus 5.5）在 Terminal-Bench 4.0 上拿到 70.6%——比 Opus 5.5 的 66.4% 还高 4 个点。Artificial Analysis Index 上得 56 分，仅次于 Opus 5.5 2 分。价格维持 Sonnet 标准 $2/$10 per M tokens。Artificial Analysis 提到它「输出 tokens per task 创新高」，意味着同任务下响应更短、更高效。

为什么重要：在 DevDay 之前 1 天发布，时机微妙——Anthropic 用 Sonnet 5.5 的「次旗舰反超旗舰」对位 OpenAI 即将发布的 Sol。70.6% 在 Terminal-Bench 上是很硬核的指标（这是测真实 CLI 多步任务的 benchmark），而且「output tokens per task 创新高」说明 Anthropic 在做和 GPT-6.1 Sol 同样的事——用同样的 cost 拿到更多 intelligence。OpenAI / Anthropic 在「次旗舰 = 大部分人用干 × 80% 工作」的赛道上正式相遇。
对你意味着什么：① 如果正在做 coding agent / terminal agent，Terminal-Bench 4.0 应该成为你的选型 benchmark——Sonnet 5.5 的 70.6% 是当前公开最高分。② Sonnet 5.5 比 Opus 5.5 便宜 5×，很多原来用 Opus 的场景可以无痛迁到 Sonnet 5.5——尤其是 code review / refactor 这种「不难但量大」的任务。③ Anthropic 在压「per-task output token 数」这个指标——意思是厂商正在按「完成任务的有效 token 量」定价，你做 agent 时也应该按「实际产出价值」做 ROI，不是按 raw token 数。

7. GPT-6.1 Sol — 「near-Astra, 1/5 价格」，价格战正式打响

P0 DevDay 主角 OpenAI · 9月29日 · TechCrunch · GPTunnel 深度 · 对比视频

GPT-6.1 Sol 价格 $2 input / $10 output per M tokens（Astra 是 $10/$50）。OpenAI 官方说法：「显著超过 GPT-6 Sol，在代码、debug、document understanding、多步业务工作流上接近 Astra」。

为什么重要：这是 OpenAI 第一次把「次旗舰 = 旗舰 80% 能力 / 20% 价格」作为明确产品定位。和 Sonnet 5.5（$2/$10）撞价——Anthropic 和 OpenAI 在次旗舰价格点上正式「对接」。这意味着 agent 应用的 token economics 出现拐点：以前「用旗舰 vs 用次旗舰」取决于场景，今天开始绝大多数任务用次旗舰就够，旗舰留给真正难的 reasoning。
对你意味着什么：① 本周重算你的 agent cost 模型——如果之前用 Astra，迁到 Sol 同样的 token 量砍 80%。② 注意 Sol 主打的「代码 / debug / document understanding / 多步 workflow」这 4 个场景——这正是企业 agent 最常见的 4 类任务，你可以直接把 80% 的 production 流量切过去。③ 第三方 prompt cache / 长上下文优化方案会受影响——Sol 出来意味着 prompt cache ROI 需要重算，因为 Sol 本身已经够便宜。

8. ArXiv 9月25日特辑：KV-streams + GroupMask + MinkowskiPE —— 长程 agent 训练基础设施齐活

P0 arxiv · 9月25日批次 · theaireport 综述 · 中文 arxiv 速览 #2464

ArXiv 9月25日发布的多篇 paper 围绕「长程 agentic RL 训练基础设施」同步推进：① KV-streams：面向 agentic RL 的长轨迹上下文压缩，降低 GPU 内存瓶颈，是长程 agent 训练的关键基础设施；② GroupMask：层自适应稀疏化，工程上可立即落地的量化方案；③ MinkowskiPE：时空位置编码，提升长序列推理质量。同期还有 Maat（多智能体合同治理）、HyperMCTS（long-horizon 规划）、Residual Authority Replay（权限持久化）等 agent 可靠性方向 paper。

为什么重要：「长程 agent 训练」是 2026 下半年最被低估的工程瓶颈——大多数团队卡在「context 长到 OOM」或「agent 跑了 100 步就迷失」上。KV-streams 是给 agentic RL 准备的「memory highway」，配合 GroupMask 的稀疏化，能让 100K+ token 长程任务在单卡 H100 上跑得动。这意味着「自训练 agent」这个以前只有大厂玩得动的领域，开始对中型团队开放。
对你意味着什么：① 关注 KV-streams 的开源实现——如果 PyPI 有包，本周就能把它接入你现有的 long-horizon agent。② GroupMask 这种「layer-adaptive sparsity」对端侧部署是关键——量化 + 稀疏化组合可以让 7B 模型在消费级 GPU 上跑。③ Residual Authority Replay（arxiv 2609.33910）对所有做企业 agent 的团队是必读——它处理「用户授权跨 session 持久化」这个真问题，避免「我 5 分钟前授权的事 agent 现在不记得」这种 UX 灾难。

9. Mistral Small 4 — 119B MoE（6.5B active）的「reasoning + non-reasoning」双模开源

P1 Mistral · 8月发布，Mozilla Firefox 9月16日集成 · Mozilla × Mistral · Artificial Analysis

Mistral Small 4：119B 总参 / 6.5B active 的 MoE，同时支持 reasoning 和 non-reasoning 模式。Mozilla 把 Mistral Small 4 放进 Firefox Smart Window beta——这是第一个进入浏览器默认助手菜单的开源权重模型。

为什么重要：Mistral 在「小模型 vs 大模型」的赛道上提供了一个清晰的对比样本：同样支持 reasoning 的 6.5B active 模型，能力能不能比肩 70B dense？如果能，MoE 路线会成为小模型效率革命的下一个主战场。Mozilla 把 Mistral Small 4 放进 Firefox 默认助手是「开源模型进入浏览器 OS」的标志性事件——之前 Chrome / Safari 都是 Gemini / Apple Intelligence 这种闭源模型。
对你意味着什么：① 如果做浏览器侧 agent 集成，Mistral Small 4 是当前最值得评估的开源后端——Firefox 已经验证了。② MoE 模型「6.5B active」意味着推理硬件要求和 7B dense 一致，但能力上限是 119B dense 的水平——性价比拐点。③ reasoning + non-reasoning 双模是 Agent 的标配能力——做选型时一定要选支持模式切换的模型，否则你得自己实现 router。
