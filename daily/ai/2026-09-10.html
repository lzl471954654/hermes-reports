OpenAI 宣读 Navier–Stokes 千禧年问题"已解"——1 万个 agent 跑 88 小时，但 credit 争议把数学圈撕了

Multi-Agent OpenAI 学术诚信 M&A 阴影

披露: 2026-09-08 · 来源: OpenAI 官方论文 · CNBC · NYT · Axios · MathOverflow

发生了什么：9 月 8 日，OpenAI 发布 《On the Navier–Stokes Millennium Prize Problem》——一份 166 页的预印本 + Lean 形式化代码，声称由约 1 万个协作 agent 的 agent swarm，在 未公开的内部模型上跑了 88 小时，首次给出三维 Navier–Stokes 方程有限时间内出现 blow-up（奇点）的构造性证明。如果被同行验证成立，意味着 Clay 数学研究所 7 个千禧年问题中第一个被攻克，对应 100 万美元奖金。

这条新闻真正重要的地方：

  • "10000 个 agent 跑 88 小时"是头条里的头条——这是「长 horizon + 多 agent 协调 + 形式化验证」第一次同时出现在一个数学突破里。它不再是「让 LLM 当个计算器」，而是把一整支 agent 队伍当研究组用：拆问题、并行尝试、形式化校验、把通过的构造拼成完整证明。Anthropic 9 月初用 Claude 11 天形式化费马大定理（详见 Anthropic 官方）是前奏，今天 OpenAI 直接放到 10000 agent 规模。
  • 「未公开的内部模型」+「不公开具体架构」是 Anthropic 没做的。Anthropic 费马证明用的是已发布模型，OpenAI 这次是「opaque breakthrough」——你能用我的结果，但你看不清我用了什么。这意味着「模型 + agent 基建」开始变成科研端的护城河，类似当年 AlphaFold 之于蛋白质结构。
  • 但 credit 争议几乎同步撕开了数学圈的共识：NYU 数学家 Tristan Buckmaster 9 月 7 日公开 3 篇相关预印本（与 Anthropic 研究员 Levent Alpöge 合作，方向是更简单的简化方程的 blow-up）。Buckmaster 声称 OpenAI 在联合署名阶段单方面要求他移除 Alpöge——也就是说 OpenAI 的"独立突破"很可能借了 Anthropic 那边的人。OpenAI 自己承认"不能完全排除间接关联"，但否认直接使用 Buckmaster 数据。NYT、Axios、Techmeme、MathOverflow 上的讨论到今天都还在升温。

冷静读法（主观判断，供参考）：

  • "Navier–Stokes 已解"这句话现在还不能用。MathOverflow 上的讨论指出证明的关键是构造一个"自相似背景 + 振荡修正来抵消动量残差"，但 Lean 形式化是否端到端通过、关键引理是否独立验证，目前都没有第三方的正式结论。CNBC 标题用"says"而不是"shows"，正是这个原因。
  • credit 争议比证明本身更有行业意义——它意味着 AI 实验室之间的科研合作已经从"互相引用"升级到"互相争夺 first authorship"，而 agent 协作又让"到底谁的功劳"变得更模糊。Bloomberg 9/8 报道 Anthropic 已悄悄退出对 Decart 的 60 亿美元收购，同期 MathOverflow 上同行对 OpenAI 数学成果的争论——Anthropic 的损失、OpenAI 的争议，同一周撞在一起，不是巧合。
  • 对做 agent 工程的人，这才是真正的新基线——之前大家卷的是"single agent + 单次工具调用"，现在天花板变成"10000 agent × 88 小时 × 形式化校验"。这不是 demo，是可复用的科研 agent pattern：子任务并行、自动形式化、长时间不回退。

对 agent 开发者的启示：

  • Agent swarm + 形式化校验器，正在变成"严肃问题"的标配。Lean、Coq、Isabelle 这类证明助手的工具链需要提前搭好——不要等大新闻出来才发现自己跑不动长链验证。
  • "未公开模型 + agent"是不透明的，复现性为零。如果你做的是 to B/科研 agent，把可复现性作为差异化卖点；不要跟着 OpenAI 学"封闭模型 + 惊人成绩"的路线。
  • "agent 协作中的 credit 分配"很快会变成行业标准——这个争议可能倒逼出类似 software bill of materials 的 agent 贡献声明协议。早期做 agent orchestration 框架的人，可以考虑加一个「贡献溯源」特性。

"OpenAI 把'agent swarm 攻克千禧年问题'这种故事讲出来的同时，credit 争议也跟着讲了出来——后者可能比前者更影响接下来 12 个月的研究合作方式。" — 编辑立场

OpenAI GPT-6 Astra 正式发布：retained reasoning + compaction，ARC-AGI-3 拉到 98.6%、Coding Agent Index 成本砍一半

Reasoning OpenAI Cost

披露: 2026-09-03 · 来源: OpenAI Release 页 · Simon Willison 测评 · ai.rs 基准

发生了什么：OpenAI 9 月 3 日发布 GPT-6 Astra，定位为"新一代智能 + 对齐的旗舰模型"，核心特性是 retained reasoning（保留推理过程）和 compaction（压缩中间状态）。这两项让模型在 OSWorld 2.0 电脑操作拿 72.6%、ExploitBench 100%、SRE-Bench 单次尝试 88.0%，Coding Agent Index 上 max effort 与 GPT-5.6 Sol 打平，但每任务成本不到 Claude Fable 5 的一半。

ARC-AGI-3 上 adapter harness 跑出 99.9%，但要注意：OpenAI 自己 7 月发的博客就披露这两项 harness 设置把同一个 benchmark 分数「tripled」——也就是说这次高分很大一部分来自推理时的 harness 工程，不是模型本身的天花板。值得跟读的是 aiweekly/Simon Willison 的两条独立验证。

对 agent 开发者：retained reasoning 是真正的杀手锏——它让 agent 在「多轮 + 多步 + 需要回溯」的任务里不需要把整个对话重新算一遍。如果你的 agent 任务有 50+ 轮，一定要在 GPT-6 Astra 上跑一次 A/B，对比 Sonnet 5 / Fable 5 的 cache 命中率。

Hugging Face funes：给 coding agent 一份"你可以拥有的长期记忆"，官方称上下文成本砍 8x

Memory Efficiency Hugging Face

披露: 2026-09-03 · 来源: HF 博客 · GitHub repo · AIBreakingWire

发生了什么：Hugging Face 9 月 3 日开源 funes——一个本地长期记忆层，把 Claude Code、Codex、pi、Hermes 等 coding agent 的历史 session log 索引成本地 Lance 数据库里，agent 任何时候可以用一行命令召回过去决策 / 推理 / 结论。HF 自己 benchmark 称上下文成本砍 8x。

为什么这件事在"小模型 & 效率革命"和"agent 前沿"两条线上同时重要：

  • "agent 记忆"是当前最大的 token 黑洞。Claude Code / Codex 一个项目跑下来经常几万到几十万 token，全靠 context window 硬塞是烧钱烧出来的"假记忆"。funes 把记忆从"每次都重读一遍"变成"按需检索"，这是把 Anthropic / OpenAI 的 cache read 范式搬到了开源。
  • 它直接挂 Claude Code / Codex / Hermes Agent / pi——意味着 funes 一发布就接入了整个主流 coding agent 生态，门槛只是"装一下 Lance + 跑一下 index"。
  • 本地 + 可控——所有 session log 不出机器，对国内团队 / 合规敏感团队是天然的合规记忆层。

对 agent 开发者：如果你在做 coding agent 或者生产环境的 agent 编排，funes 是 2026 年最值得评估的开源记忆层之一——比自建 pgvector + summarizer 至少省一个工程师月。建议先在 1-2 个项目上跑起来，看 hit rate 和 token 节约是否真能到 8x（很多 case 会比这个乐观值低，但 2-3x 是稳的）。

Prime Intellect 开源 Prime Agent：自改进 RLM harness，ARC-AGI-3 上 95.5%

Self-Improving Open Source RLM

披露: 2026-08-05/06 · 来源: Prime Intellect 官网 · arXiv 论文 · OpenSourceForU

发生了什么：8 月初，Prime Intellect 开源 Prime Agent（MIT）——一个"自改进的 coding/research harness"，核心创新是递归语言模型 (RLM) + continual harness（跨任务持续改进的 harness）。模型的主要工具不是固定 tool 列表，而是一个持久的 Python notebook。配 Claude Opus 5 在 ARC-AGI-3 上跑出 95.5%。

关键要看清的是「范式」而非「分数」：

  • 「self-improving harness」是 agent 工程的下一个分水岭——之前的 agent 把"改进"留给训练阶段，runtime 不学。Prime Agent 让 harness 自己写经验、跨 session 沉淀，这正是 OpenAI 10000 agent swarm 在数学上用的同一思想，只是开源版。
  • Python notebook 作为主要工具——这等于把 agent 的执行空间从"tool calling 的固定集合"升级成"任意可组合的代码"，本质上是一个更通用的 REPL 范式。类比：从 CLI 工具升级到 REPL。
  • MIT license + 公开 RLM 论文——意味着可以做商业化二次开发，不像很多 agent 框架是 source-available。

对 agent 开发者：如果你的 agent 是"长 horizon + 复杂研究 / 编码"方向，Prime Agent 是比 LangChain / AutoGen 更值得关注的新基线。值得花一个下午读一下它的 RLM 论文，再决定要不要把内部 agent runtime 切到这个 harness 上。

IFM 发布 K2 Horizon：6 个 Apache 2.0 模型（0.9B-375B）+ MoVA 稀疏注意力架构

Open Weights IFM Edge

披露: 2026-09-03 · 来源: IFM 官方博客 · HF 模型页 · MarkTechPost

发生了什么：独立 AI 实验室 IFM 9 月 3 日发布 K2 Horizon——一队 6 个 Apache 2.0 模型（0.9B / 3.7B / 7B / 36B-A4B / 175B / 375B-A23B），完整开源权重 + 中间 checkpoint + 训练代码 + 数据 recipe + 训练日志。核心新架构是 MoVA（稀疏注意力变体）+ Uno decoding 加速。亮点 benchmark：

  • 7B 在 SWE-bench Verified 上 70.6、BrowseComp 59.0
  • 3.7B 在 SWE-bench Verified 上 68.6（小模型代码能力新 SOTA）
  • 0.9B 在 AIME 2026 48.5、HumanEval+ 79.9（量化后可跑在手表上）

真正值得盯的不是分数，而是"完整开源 + 训练数据 + 训练日志"这件事本身。

  • DeepSeek、Qwen、LLaMA 的"开放"基本停在权重层。K2 Horizon 把训练 recipe 和日志也放了，意味着你可以在它基础上微调、做合规审计、做学术研究——这是真正意义上的"research-grade open source"。
  • 3.7B 模型 SWE-bench 68.6 比很多 7B 模型还强，对端侧 coding agent 是直接利好。
  • MoVA 稀疏注意力 是继 DeepSeek V3 的 DeepSeekMoE、Llama 4 的 MoE 之后的又一个稀疏范式，值得跟读后续 paper。

对 agent 开发者：如果你的产品对数据合规有要求（金融、医疗、政企），K2 Horizon 这种"全栈开源"模型比闭源 API 更适合做底座——审计成本低一个数量级。先在 3.7B / 7B 上做一轮 agent benchmark，看是否替换你现有的开源模型。

GitHub i-have-adhd 爆火：让 coding agent 别再「埋答案」，25k stars

UX Open Source

披露: 2026-09-08 · 来源: GitHub repo · LinkGo 评测

发生了什么：HN 9/8 首页热门 —— i-have-adhd（ayghri/i-have-adhd）是一个 Claude Code / Codex / 任何读 AGENTS.md 的 coding agent 都能装的 skill。规则很朴素：先给命令、再列编号步骤、列表不超过 5 项、删掉前言/复述/收尾客套。MIT license，25k stars。

看似玩具，其实反映了一个真实的 agent UX 问题：

  • LLM 默认输出臃肿——RLHF 把"详细礼貌"的回答当作正向信号，agent 场景下反而成了噪声。
  • 「AGENTS.md + skill 协议」让"行为模式"可分发——i-have-adhd 装一次就改 agent 全局行为，比 prompt 微调更稳。
  • 25k stars / 9 月初发，增速比 LangChain 当年同阶段还快。

对 agent 开发者：如果你的用户吐槽"agent 回答太长，找不到重点"，直接 fork i-have-adhd + 改成你自己的 brand voice，比改 system prompt 长期靠谱。skill 协议正在变成"agent UX 的 npm"。

💭 深度思考

洞察 1：OpenAI vs Anthropic 这一周的"反向并行"——是行业结构的拐点信号

把这一周的几个事件放在一起看，会发现一个有意思的「反向并行」：
