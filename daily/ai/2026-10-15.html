1. Cursor 把 MoE 训练做成单一 kernel——Mixture-of-Kittens 开源，NVL72 上每层 2.37×、端到端 41% 加速

P0 开源 效率 MoE 训练 Cursor · 报道 / 数字来源

发生了什么：Cursor 开源了 Mixture-of-Kittens，一个把 MoE 训练全流程（dispatch + combine + 优化器 state）压缩为 单一 GPU kernel 的实现。在 NVIDIA NVL72 rack 上，单层 forward+backward 提速 2.37×，端到端训练快 41%。

  • MoE 是 Qwen3 / DeepSeek V3 / Nemotron 的主流架构，省 FLOPs 但 路由 overhead 一直是训练瓶颈；
  • 过去靠 专家并行 + 张量并行 + DP 拼，写起来累、通信贵；
  • "fuse 成一个 kernel"是 flash-attention 当年走过的路，MoE 圈终于跟上。
为什么重要：开源 + vendor-agnostic kernel = 小模型实验室自己训 MoE 的壁垒塌一档。过去要复现 Qwen3-30B-A3B 必须有 8×H100 + DeepSpeed 团队，现在一个消费级工作站在 NVL72 上也能匹敌原厂的端到端速度。主编观点：这是 2026 年下半年被低估的一条线—— "训练成本"压得越低，agent 用小模型 fine-tune 的经济性越成立。

4. arXiv 2610.05223《Look Before You Leap》——LLM agent 自调记忆架构，参数化与非参数化知识"热力学仲裁"

P0 10 月 memory RAG Akash Das Akash Das et al. · arXiv 2610.05223

发生了什么：10 月新预印本提出 "Thermodynamic Arbitration" 框架，让 LLM agent 实时在"用参数化记忆（已学到）"和"用非参数化记忆（外部 RAG / 工具）"之间做带温度参数的决策。Self-Regulating Memory Architecture 在多 agent 工具调用场景里避免掉过多的检索 / 工具调用。

  • 触及 agent 设计里一个老问题："我知道 vs 我去查"——很多 agent 工具调用成瘾，明明参数里就有答案仍然盲目检索；
  • 论文 10 月版本用"热力学"框架给出 随上下文长度 + task confidence 动态切换 的策略；
  • 和另一篇 arXiv 2610.06191 "Judged Useless, Queried Anyway" 形成对话——后一篇实证发现当前 tool-using agents 很少把自己的"判断无用"信号转成 stop decision。
对 agent 开发者意味着什么："tool use 节流"从工程黑话变成论文主语。主编观点：12 个月前大家最关心"agent 怎么调用工具"，现在第一问题变成 "agent 何时应该不调用工具"—— 这个反转是 agent 行业成熟的标志。
