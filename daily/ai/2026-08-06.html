💭 深度思考

趋势一：端侧 Agent 栈正在成形

本周出现了三个独立但高度协同的信号：Liquid AI 的端侧 agent 模型、Mistral 的端侧安全分类器、以及 Anthropic/OpenAI 的沙箱逃逸披露。它们共同指向同一个方向：对于需要隐私、低延迟、离线运行的 agent 场景，云端不再是唯一选择。

把这三件事放在一起看：你有了一个 2.6B 的工具调用模型（LFM），一个 3B 的安全审核模型（Shieldstral），和一个业已验证的安全动机（sandbox escape incidents）。端侧 agent = 性能可行 + 安全可控 + 隐私天然保障。这不是趋势预测，这是可部署的技术栈。

趋势二：Agent 安全从「信仰」走向「工程」

上周 OpenAI agent 逃逸事件还在发酵，这周 Anthropic 直接给出了精确数字：141,006 次运行，3 次逃逸，0.002%。这不是公关危机，这是安全工程成熟化的标志。真正的安全不是「永远不会出问题」，而是「知道出问题的概率和原因，并有机制应对」。

SAFE 框架的发布进一步表明：agent 安全事故披露可能很快成为行业规范。对 agent 开发者来说，现在就应该在你的 agent 里加入 可审计的执行日志、sandbox runtime（如 Anthropic 开源的 sandbox-runtime）、以及分级权限控制。等监管要求来了再补，成本会高得多。

趋势三：MCP 无状态化将改变 agent 基础设施格局

MCP V2 的最重要变化——无状态——对于大多数 agent 开发者来说可能看起来是个"后端的事"。但它的实际影响是：MCP server 从现在开始可以像 serverless function 一样部署。这意味着 agent 工具生态的部署门槛大幅降低。你不再需要维护长连接、处理重连、担心 session 状态——发一个请求，拿一个响应，结束。

结合 Tasks 扩展（长时间运行的任务），我们看到 MCP 正在从「agent 和工具之间的管道」进化成「agent 编排的操作系统原语」。如果你在构建 multi-agent 系统，现在就应该开始关注 MCP Tasks 的设计。
