1. LongHorizon-Harness：用任务状态管理解决长程 Agent 的核心难题

Agent 架构 arXiv 开源

AMAP-ML 团队在 arXiv 上发布了 LongHorizon-Harness（arXiv:2608.01964，8月3日），提出了一个全新的 Agent 架构思路：将长程任务重新定义为任务状态管理问题。框架引入三个结构化角色——Manager（规划）、Executor（执行）、Auditor（审计），最关键的设计是：任务状态独立于 Agent 上下文窗口之外维护，只有经 Auditor 独立验证为真的事实才能更新状态。

💡 这意味着什么：当前大多数 Agent 框架把任务状态、执行过程和完成评估全部塞进同一个不断膨胀的上下文中。这导致两个致命问题：状态追踪困难，以及 Agent 的"自我感觉良好"（错误地认为自己完成了任务）会污染后续决策。LongHorizon-Harness 用操作系统级别的思路——分离状态与执行、引入独立验证——解决了这个问题。目前已适配 Claude Code、Codex CLI 和 OpenClaw。如果你在构建需要多步骤、长时间运行的 Agent 系统，这个框架的设计思想值得深入研究。

来源：arXiv · GitHub · Hugging Face

2. NVIDIA NOOA：一个 Agent = 一个 Python 类

Agent 框架 NVIDIA 开源

NVIDIA Labs 于 8月7日开源了 NOOA（NVIDIA Object-Oriented Agents），一个模型无关的 Python Agent 框架。其核心思想是：把 Agent 的能力、状态、提示词、工具全部封装到一个 Python 类中——通过方法、字段和 docstring 来定义，而不是分散在提示词模板、工具 schema、回调函数和工作流图中。

实际表现：在 SWE-bench Verified 上，NOOA + GPT-5.5 达到了 82.2%，仅使用约 29 次 LLM 调用和 ~1.1M tokens。参评专家指出，这种"一个类一个 Agent"的设计让测试和审查变得更容易，但也带来了新的安全问题。

💡 Agent 开发者的启示：NOOA 代表了 Agent 框架设计的一种"反碎片化"趋势。当前 Agent 开发中，提示词、工具定义、状态管理、回调逻辑散落在不同文件中，维护和调试极其痛苦。NOOA 的 OOP 思路虽然不新，但在 Agent 领域是一个务实的选择。不过，它的简单性也意味着复杂编排场景可能需要额外层。

推理优化 FPGA FCCM 2026

FCCM 2026 接收论文 LUT-LLM 提出了首个支持 10 亿参数以上语言模型的 FPGA 加速器方案。通过向量量化和基于查找表的内存计算，在 AMD V80 FPGA 上实现了 比 NVIDIA A100 GPU 高 3.05~6.60 倍的能效，算术运算减少 4 倍，并支持扩展到 320 亿参数模型。

上下文优化 学术
