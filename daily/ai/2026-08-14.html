DeepSeek V4 Pro 0813 正式版：开源权重模型在 Agent 基准上反超 Claude Opus 4.8

P0 · 模型发布 + Agent 8月13日 23:00 北京时间 · DeepSeek

昨晚深夜，DeepSeek 把 V4-Pro 0813 正式版铺到了 app / web / API 全渠道。这是 DeepSeek 1.6T 参数 MoE 旗舰（49B 激活参数）的 GA 版本，也是今天所有动态里分量最重的一条——因为它的意义不在「又一个大模型」，而在开源权重的 agent 能力第一次在官方口径上反超了 Anthropic 的旗舰 Claude Opus 4.8。

几个硬数字：

  • Terminal-Bench 2.1 从 Preview 版的 72.1 一路拉到 87.9，这是终端/仓库级 agent 任务里目前最硬的指标之一；
  • 官方评测里，在 HLE、Terminal-Bench、Cybergym、DeepSWE 等 Agent 能力上超过 Opus 4.8，逼近 6 月发布的 Fable 5，部分榜单实现反超；
  • SWE-bench Verified 80.6%（V4-Pro-Max 模式），发布时开源权重模型的最高分；
  • 原生 Responses API + Codex 接入、reasoning-effort 控制、1M 上下文 / 384K 输出。

价格才是真正的杀招。第三方渠道（OpenRouter）挂出的价格是 $0.435/百万输入、$0.87/百万输出——对比 Claude Opus 4.8 的 $5/$25，输入约为 1/11、输出约为 1/29。换句话说：一个 agent 用 DeepSeek V4 Pro 跑长程任务，token 成本可能是 Opus 4.8 的几十分之一，而官方自报的 agent 分数还更高。

为什么这很重要：这不是「便宜但差一截」的性价比故事，而是开源权重在「agent 可靠性」这条最关键的赛道上，第一次和前沿闭源贴身肉搏还占了上风。昨天日报的「深度思考」里我写过「模型正在零件化、harness 才是护城河」——DeepSeek V4 Pro 0813 就是这条判断最锋利的一次兑现：当 1.6T 开源模型的 agent 能力反超 $5/$25 的闭源旗舰时，「用哪个模型」这件事本身不再构成任何人的差异化。

对 Agent 开发者的启示（主观判断，标注清楚）：如果你在跑多步 coding agent、CLI/终端型 agent 或长文档分析，DeepSeek V4 Pro 0813 值得在本周内上 OpenRouter 实测一遍。但注意三点：一是官方调价方案尚未公布（财联社明确写了「尚未公布调价方案」），第三方价格先别当长期锚点；二是 DeepSeek 的 benchmark 自报成分需要第三方交叉验证，尤其 DeepSWE / Terminal-Bench 这种最硬的任务，用你自己的工作流测一遍再下结论；三是「开源权重」和「可复现部署」是两回事，模型卡已在 HF 上，但 serving 它需要 1.6T 权重的数据中心级资源，别把它和「本地能跑」混为一谈。

论文：推理模型「想得用力，但不会省着用」——无法在多题之间合理分配 test-time compute

P0 · 推理效率 arXiv:2608.07968 · 8月

这篇题为 「Thinking Hard, Not Smart: Reasoning Models Fail to Ration Test-Time Compute Across Questions」的论文点破了一个被市场忽略的短板：现有推理模型的评测几乎都是「一题一算」——每个问题单独给足 test-time compute。但真实场景（尤其是 agent 批量跑任务、API 按 token 计费）里，算力是一个需要在多个问题之间共享的预算。作者的发现是：推理模型不知道该怎么把这个共享预算「花在刀刃上」——它只会对每个问题都「用力地想」，而不是「聪明地省着用」。

为什么这和今天的 DeepSeek / Gemini 动态直接相关：当模型价格打到 $0.435/$0.75 这种量级，厂商和开发者都开始关心「同样一块钱，怎么买到最多的正确率」。这篇论文给出的答案是：光靠模型降价不够，还需要「预算分配」这一层智能——而这层智能目前是缺失的，必须由外部的 routing / 预算控制器来补。

给 Agent 开发者的 actionable 建议：如果你在跑「批量推理」型 agent（比如同时处理几百个 issue、几千条文档），别用统一的 reasoning effort 一刀切。做一个轻量的难度预估/路由层：简单任务用低 effort 或小模型，把省下的 compute 集中投给难任务。今天这篇论文从机制上证明，模型自己做不到这件事——「算力预算调度」是留给你这个编排层的活儿，也是下一个能做出差异化的地方。

💭 深度思考

📌 观点一：开源权重的「agent 能力」已经和前沿闭源贴身肉搏，价差拉到一个数量级以上

把今天的三件事并排看：DeepSeek V4 Pro 0813（1.6T，$0.435/$0.87）在 HLE/Terminal-Bench/DeepSWE 上反超 Opus 4.8（$5/$25）；Qwen3.8-Max（2.4T，$2/$6）承诺开源；Qwen3.8-27B 主打「智能密度」单卡可跑。它们叠加出的图景是：「开源 + 白菜价 + agent 级能力」第一次同时成立。

这直接续上了昨天日报的判断——模型正在「零件化」。但今天的证据让这条判断更硬了：不只是中端模型在零件化，连「能打 agent 硬仗」的旗舰级能力也开始零件化。当 1.6T 开源 MoE 能以 1/11 输入价、1/29 输出价做到和 $5/$25 闭源旗舰相当甚至更高的 agent 分数，闭源厂商能守住的价值，就只剩产品层（Cursor/Cowork 的编排与分发）和「永远最新的那一两个版本」。

Actionable：如果你还没做「模型可替换」的架构，现在就是最该做的时点。把 agent 的核心逻辑和具体模型解耦，保留一个可配置的 model router——因为从今天起，最优性价比模型会以「周」为单位换庄，锁死单一模型等于把成本劣势锁死。

📌 观点二：算力预算的「调度」，是下一个比模型本身更值钱的效率战场

今天两条看似无关的线索其实指向同一处：「Thinking Hard, Not Smart」证明推理模型不会在多题之间分配 test-time compute；而 Gemini 3.7 Flash 三个月三连发、DeepSeek 把价格打到 $0.435，都在说明「单位美元的正确率」正在取代「绝对正确率」成为采购决策的核心指标。

当模型又便宜又强，瓶颈就不再是「模型不够好」，而是「你不会花算力」。这意味着一个正在成型的机会：在编排层做「compute 调度」——难度路由、effort 控制、早停、批处理时跨任务的预算分配、以及用更便宜的模型先做「试错」再用贵模型做「定稿」。

Actionable：这周就可以落地一个小实验：给你 agent 的每一步加一个轻量 difficulty estimator（甚至就用一个小模型或规则判断），简单步走 cheap/fast 模型，难步才调贵模型。你会发现在 agent 总成本上，这比「换个更便宜的模型」还能省——因为它省的是被浪费在简单任务上的推理算力。
