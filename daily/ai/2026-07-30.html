AI 蠕虫可在 Copilot for Word 中自我传播

安全研究员在博客中披露了一种新型攻击向量：文档承载的 AI 蠕虫（document-borne AI worm），可以通过 Microsoft Copilot for Word 实现自我传播。攻击者将恶意指令嵌入文档中，当其他用户通过 Copilot 打开该文档并触发 AI 功能时，蠕虫会在新文档中复制自身。

分析：这是 prompt injection 的一个危险子类——它不仅欺骗单个 AI 调用，而是利用 AI 作为传播载体实现持久化和横向移动。传统防病毒软件对这类攻击完全不可见，因为恶意载荷不是二进制代码而是自然语言指令。

对策：Agent 系统需要实现输入沙箱化（input sanitization）和上下文隔离，不能盲目信任用户提供的文档内容。MCP 服务器的输入验证将成为标配。

Kimi K3：首个开源 3T 级模型，四大架构创新

月之暗面（Moonshot AI）的 Kimi K3 预览版发布，这是目前首个开源的 3T 参数级模型。根据 Embedl 在 HF 上的深度技术解析，K3 的架构包含四项关键创新：

  • Kimi Delta Attention：主力注意力机制，据称在长上下文效率上有显著突破
  • Gated MLA（Multi-head Latent Attention）：在 latent space 做精确的四分之一注意力计算
  • Attention Residuals：全新的残差连接设计
  • Stable LatentMoE：稀疏专家混合的稳定性改进

关键信号：中国团队在开源大模型军备竞赛中交出了一份重量级答卷。K3 的架构选择（Delta Attention + Gated MLA）不是对 GPT/LLaMA 架构的简单复刻，而是有独立技术判断的创新。这对 agent 开发者意味着：如果你在选 base model，架构多样性本身就是价值——K3 可能在长上下文 agent 任务中有独特优势。

💭 深度思考

思考一：Agent 安全正在经历「破窗期」——现在是最好的介入时机

本周最值得关注的叙事线索非常清晰：Agent 安全。从 Frontier Lab 入侵事件到文档蠕虫，从 Google Beyond Zero 到 Leanstral 的形式化验证——不同的信号指向同一个结论：AI agent 的安全基础设施严重滞后于 agent 能力的增长。

Agent 开发者今天面对的局面，很像 1990 年代末的 Web 开发者——你能做出很酷的东西，但安全模型还在襁褓中。SQL 注入在 1998 年被发现，但直到 2000 年代中期才被认真对待。今天的 prompt injection 和 agent 工具滥用就是 2026 年的 SQL 注入。

行动建议：如果你想在 agent 领域建立长期竞争优势，现在就把安全作为你系统的 first-class concern。实现输入验证、最小权限原则、审计日志——这些今天看起来是「额外工作」的东西，12 个月后将是行业准入门槛。

思考二：开源模型正在走向架构多样性——这对 Agent 生态是利好

Kimi K3 和 Leanstral 1.5 的共同点是它们都不是 LLaMA 架构的 clone。K3 有 Delta Attention + Gated MLA，Leanstral 专注于形式化验证。这意味着开源模型生态正在从「同质化追赶」进入「差异化竞争」。

对 Agent 开发者来说这是一个被低估的利好：不同 agent 任务需要不同的模型能力特征。长上下文推理 agent 可能需要 K3 架构的优势，安全关键型 agent 可能需要 Leanstral 的验证能力，而通用的对话式 agent 用 Mistral Medium 3.5 就很好。架构多样性意味着你可以针对具体场景选择最优解，而不是所有人都被迫使用同一个通用模型。
