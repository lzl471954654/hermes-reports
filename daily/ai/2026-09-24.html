Google AX：GitHub Trending 第一的分布式 Agent Runtime（9/22 发布）

P0 Googleagent runtime 开源分布式

发生了什么：Google 在 9/22 开源了 AX (Agent Executor)，定位是「开源分布式 agent 运行时标准」。9/23 即登顶 GitHub trending AI agent 分类（gittrend.io），累计 8.5k stars，其中 1.6k 是近一周新增。

AX 的核心特性：

  • Durable event log——agent 执行轨迹持久化，进程崩了能续
  • Resumable streams——长链路 agent 中断后可恢复，不是从头跑
  • Trajectory forking——同一起点可以分叉出不同探索路径
  • Isolated actors——gVisor 沙箱隔离，agent 跑代码不会污染宿主机

为什么重要：之前的 agent 框架（LangGraph、CrewAI、AutoGen）都在编排层竞争，AX 直接下沉到运行时层——而且是 Google 自家出品，等于官方背书「agent 是分布式系统」的范式。这条赛道一旦被 Google 拿走，整个 agent infra 创业公司都得让路。

对 agent 开发者的启示：

  • 先看再选：如果你的 agent 任务超过 5 分钟或者涉及长上下文，立刻去 github.com/google/ax 看 README——durable log 解决了困扰所有长任务 agent 的「崩溃恢复」问题。
  • 路线选择：如果要上生产，AX vs Agyn vs Dapr Agents 三选一，看 codepick.dev 那篇比较文；要做 demo prototype 还是 LangGraph 更快。

Jev (TypeSafe AI) System One 决策模型持续发酵：独立基准测试「6/7 缺陷捕获」

P0 TypeSafe AIdecision model RLCD新范式

发生了什么：9/15 发布、这两天（9/22-24）仍在持续刷屏的 Jev——TypeSafe AI（前 OpenAI 研究员 Diogo Almeida 创业项目）的「System One 决策模型」。不是 LLM，是返回结构化决策（choice / score / noul）的非自回归模型。9/23 出现了第一个独立基准测试（karmactive.com）。

关键数据：

  • 速度：比标准 LLM 快 193×，延迟 33ms 级
  • 价格：$0.042 / M tokens（比 GPT-4o-mini 还便宜一个数量级）
  • 幻觉：因为 schema 预先定义 valid outputs，结构上不可能 hallucinate 类型错误
  • 训练方法：RLCD（Reinforcement Learning from Calibrated Data），不是 RLHF
  • 独立测试：dylantom2012 用 Claude Code 跑了 1 天对比开源 CPU 栈，Jev 在多数任务赢 0.6 分；TrueStandard 用它做 agent 安全审查，7 个故意植入的缺陷里抓到了 6 个

为什么重要：这是 LLM 之后第一次有团队敢公开宣称「我们做的是机器原生智能，不做语言模型」。如果独立基准测试持续验证，agent 架构会从「全栈 LLM」走向「LLM 做规划 + System One 做局部决策」的两层架构——前者负责推理，后者负责分类/评分/选择，速度和成本差两个数量级。

对 agent 开发者的启示：

  • 立刻能用的场景：你的 agent 里所有「二选一 / 多分类 / 评分 / 是非判断」的环节，都可以替换成 Jev 类 System One 模型，省成本 10×，速度快 100×。
  • 代码扫描：is-malicious 这种「用 Jev 扫代码是否藏恶意行为」的用例已经开源（awesome-jev-2），可以拼到你 CI/CD 里做 PR 前置扫描。

Bartowski 推出 Per-tensor Layout Maps：GGUF 量化从「一刀切」走向「按张量精度画像」

P0 Hugging FaceGGUF quantization本地部署

发生了什么：Hugging Face 上 Bartowski 9/10 发了一篇长文 Per-tensor layout maps for GGUF quantization，9/22-24 持续刷屏。核心改动：以前 GGUF 量化时所有张量用同一组规则（Q4_K_M 就是 Q4_K_M），现在 Bartowski 给每个模型算出每个张量的 sensitivity 排名，然后把精度预算向敏感张量倾斜。

具体发现：

  • attention_v / attention_output / ffn_up / ssm_out 是最敏感的张量，每 bit 误差都会被放大
  • 小 attention projection 对精度极敏感（同 bit 下损失大于其他模块）
  • Bartowski 用 solver 跑出来的 recipe 头对头 KLD 不一定赢手工 layout——意味着未来量化工具会从「按经验」转向「按数据画像」

为什么重要：Q4_K_M 已经统治本地 LLM 部署 2 年了，现在是第一次有人系统地拆解「为什么同样的 Q4 在不同模型上效果差异那么大」。下一步是 llama.cpp 直接吃这些 layout map 自动出文件，对所有跑 7B-70B 本地模型的人都是免费提升。

对 agent 开发者的启示：

  • 如果你跑本地 Qwen3.8-27B、MiniCPM5-2B、Llama 类模型，重新下载 bartowski 9/10 之后用新 layout 出品的 GGUF，同等显存下质量更高。
  • 关注 bartowski1182 GitHub，下次出 Llama 4 GGUF 时直接选「per-tensor layout」版本。

洞察 1 · 2026 Q3 的真正主题不是「更大的模型」，是「更便宜的 agent 运营」

把过去一周的事件串起来：Opus 5.5 降价 20-60%、GPT-6 Sol/Luna 腰斩、Step 5 Preview 1/8 Opus 5 成本、Tencent Hy4 0.8× Opus、Jev 比 LLM 便宜 100×、AX 把运行时开源、Anthropic 公开 30,000 agents 内部运营数字——这些全指向一件事：

模型层的差异化在缩小，agent 层的运营成本变成主战场。谁能用更便宜的算力跑更多 agent，谁就能占领下一个季度的市场份额。这也是为什么 Jev 这种「非 LLM 决策模型」会突然冒头——不是 LLM 不够好，是 LLM 太贵了。

洞察 2 · 给 agent 开发者的 3 条 actionable 建议

  • 路由架构重做：2026 Q4 起，agent 系统默认架构应该是「Opus 5.5 / GPT-6 Astra + Step 5 Preview + Jev 类决策模型 + 本地 GGUF SLM」的四层路由。强模型做规划（<5% 调用）、开源旗舰做主要推理（~50%）、System One 做分类评分（~30%）、本地 SLM 做 hot path（~15%）。
  • 把 agent monitor 当一等公民：Anthropic 的 1/47,000 拦截率 + ChromaFlow 的 orchestration 噪声警告说明：agent 多了之后，monitor / verifier / safety check 的代码量会超过 agent 本身。现在写 agent 时同步写监控。
  • 关注 9/29 OpenAI DevDay：Managed Agents 一旦发布，所有自建 agent infra 的估值会被重估。先想清楚如果 OpenAI Agent Service 收费 $0.05 / agent-hour，你会切换还是留下——这个决策决定了你接下来 6 个月的技术债。
