Prime Agent 登上 HN 首页：「自我改进的 RLM agent」到底是不是下一范式

P0 · Agent 新范式 8月5日发布 · 本周持续发酵 · Prime Intellect

本周 agent 圈最重要的一件事，是 Prime Intellect 的 Prime Agent——一个 MIT 许可的开源「自我改进」coding harness，核心是两套抽象：Recursive Language Model (RLM) 和 Continual Harness。官方口径是：跑在 Claude Opus 5 上，ARC-AGI-3 拿到 95.5%，超过了 95.4% 的人类专家基线。这条消息 8 月 5 日发布，本周在 Hacker News 首页、机器之心「开源框架刷爆 ARC-AGI-3，自我改进 RLM harness 引争议」的标题下二次发酵——而争议本身，才是这件事最有价值的部分。

RLM 到底是什么意思：不是「又一个大模型」，而是把「递归」变成 agent 的原生操作——agent 可以在任务中途改写自己的 workflow、递归地 spawn 子 agent、把一次失败的尝试变成下一次的输入。配合 Continual Harness，它宣称会越用越强：每次跑完，验证器（verifier）打分，好的轨迹被回收进下一轮的上下文。这跟昨天我们聊的「用真实专家工作流做 post-training」是同一个思路，只是从「训练时」挪到了「运行时」。

争议点（必须标注）：「95.5% 超人类基线」是 Prime Intellect 自报数字，而且 ARC-AGI-3 这类 benchmark 对 harness 工程（提示词、verifier、重试策略）高度敏感——「自我改进」和「精心调教的刷分 harness」之间的界限，目前没人说得清。机器之心标题里那个「引争议」指的就是这个：一部分人认为这是真·范式（agent 开始具备运行时自我修正的能力），另一部分人认为这不过是把 prompt engineering 和 verifier 堆到了极致。

为什么这很重要（我的判断）：无论真相偏哪边，「RLM / verifier-driven harness」已经站上了舞台中央。上一轮 agent 竞争在拼「谁的工具调用更稳」，这一轮开始在拼「谁能让 agent 的运行时闭环——失败重试、轨迹回收、自我修正——做得更好」。对 agent 开发者来说，Prime Agent（MIT 开源）是一个可以直接拆开读源码的标本：它把「自我改进」这件事工程化成了可复制的组件，而不是一篇论文里的口号。

Actionable：别急着信「95.5%」，但值得做两件事：① clone 下来，看它的 Continual Harness 怎么收集和回收轨迹——这是「把 agent 运行日志变成改进燃料」的现成参考实现；② 把你自己的 agent 换成「verifier + 轨迹回收」的结构，哪怕只加一个简单的「成功/失败重试 + 好轨迹进上下文」的循环，通常就能在不换模型的前提下拿到可观的稳定性提升。

Gas Town（Steve Yegge）重回视野：git 背书的「20-30 个 agent 并行协作」状态持久化

P1 · Multi-agent 编排 本周 · 机器之心重新报道 · 项目自 1 月起

机器之心本周把 Steve Yegge 的 Gas Town 又翻了出来——一个为 Claude Code / GitHub Copilot / Codex 等设计的 multi-agent 编排系统，核心卖点是用 git worktree + Beads 账本把每个 agent 的工作状态持久化，让 agent 重启或崩溃后不丢上下文，号称能同时协调 20-30 个并行 agent。

点评：它解决的是 multi-agent 落地时最脏的一环——状态持久化。Prime Agent 在做「自我改进」，Gas Town 在做「多 agent 不塌房」，两条线合起来指向同一个结论：agent 基础设施的竞争焦点，正从「单次回答好不好」转向「长时间、多进程、可恢复地干活」。如果你正在跑多个 Claude Code 实例并行改代码，它的 git-backed hook 思路值得抄。

Meta Muse Glimmer：30B 开源本地 agent 模型落地，正面撞上 Qwen3.8-27B

P0 · 小模型/本地 agent 8月10日 · Meta

Meta 放出了 Muse Glimmer：约 30B 参数（29.6B）的 dense 多模态模型，Apache 2.0 许可，权重发布当天就上 Hugging Face。定位精确——「专为本地 agentic 场景设计」：通过 4-bit 量化 + DFlash 推测解码，在单张消费级显卡上、20GB 以内就能跑。它不是「把 Muse Spark 解封」，而是从旗舰 Muse Spark 蒸馏出来的 student（logit distillation + mid-training + SFT + on-policy distillation + RL）。

为什么是 P0：这是 Meta 对「本地 agent 模型」这条线最直接的一次押注，而且直接撞上我们昨天重点说的 Qwen3.8-27B。第三方对比的初步共识很有意思：Muse Glimmer 在工具编排（tool orchestration）上领先，Qwen 在纯 coding / computer use 上更强。换句话说，「本地 agent 底座」这个位子，Meta 和阿里正在用两条不同的侧重点抢——一个偏「agent 稳定性/工具调度」，一个偏「代码能力」。

Actionable：如果你在做本地 agent，现在是做 AB 的最佳时点：两个都是 Apache 2.0、都能单卡跑、都宣称原生 tool-calling。建议用你的真实 agent 工作流（不是刷 benchmark）分别跑一遍，重点测三件事：多轮 tool calling 的稳定性、中文能力、以及量化后（4-bit）的延迟/显存。上一代 Qwen3.6-27B 的「中文弱」痛点，这次该验证 Muse Glimmer 是否填补了「中文 + 1-3B 端侧」之外的本地 agent 空白。

GPT-5.6 Sol Ultrafast：Cerebras 晶圆级芯片把推理推上 14 倍速、750 token/s

P0 · 推理效率/速度 8月13日 · OpenAI × Cerebras

OpenAI 预览了 Ultrafast 模式：由 Cerebras 的晶圆级（wafer-scale）芯片驱动，跑 GPT-5.6 Sol 高达 14 倍速、峰值 750 输出 token/s，官方强调「无质量妥协」。对比口径很凶：比 Claude Opus 4.8 的 Fast 模式快 5 倍、比 Claude Fable 5 快 11 倍。目前是 select customers 的 preview，价格未公布。

为什么这重要：昨天我们在聊「算力预算调度」和「always-on agent 的成本」，Ultrafast 补上了拼图的最后一块——速度。当 agent 需要多步、长程、实时交互（比如一边跑工具一边等结果），750 token/s 和 50 token/s 的差别不是体验问题，而是「这个 agent 能不能真的常驻」的可行性问题。Cerebras 用「一整片晶圆当一颗芯片」绕开了 GPU 集群的显存带宽墙，这解释了为什么它能比传统部署快一个数量级。

Actionable + 一个 caveat：这直接利好「frontier 模型 + 高频低延迟 executor」的架构——把需要前沿智力的长程任务交给 Sol（需要时上 Ultrafast），把高频杂活交给 Nemotron Lightning 这类小 executor。但注意两点：① 750 token/s 是「输出」速度，不是端到端首 token 延迟，别把峰值数当成交互体验；② 这是 preview、价格未出，「14 倍速」最终划不划算要看溢价——如果每 token 贵 14 倍，那对大多数 agent 毫无意义，它真正的价值在「等不起」的实时场景。

💭 深度思考

📌 观点一：「自我改进」正在从论文概念，变成可 clone 的运行时组件——而它的护城河是「轨迹」

把 Prime Agent（RLM + Continual Harness）、昨天的 GLM-5.3（post-training 用真实专家工作流）、以及 Gas Town（轨迹/状态持久化）连起来看，一条主线呼之欲出：agent 的价值正在从「模型权重」转移到「运行时产生的轨迹数据」。Prime Agent 的「自我改进」本质上就是「把成功轨迹回收到下一次运行」，GLM 的「专家工作流 post-training」是「把轨迹回收到下一次训练」，Gas Town 是「让轨迹别丢」。三者是同一个东西在三个不同时间尺度上的投影。

Actionable：如果你在构建 agent，你现在手里最值钱的资产不是选哪个模型，而是你的 agent 每次运行留下的「成功/失败轨迹」。哪怕先用最笨的办法——把成功任务的完整上下文 + 工具调用序列存下来，作为下次类似任务的 few-shot 前缀——就足以让稳定性和质量有明显提升。这是闭源厂商替你做不了、而你能直接做的一步。别把日志当垃圾删掉。

📌 观点二：速度、成本、规模三路同时下探，「always-on agent」的经济账正在被算平

这一周的三条效率新闻——Ultrafast（14 倍速）、Gemini 3.7 Flash（$0.75/M）、Muse Glimmer/Nemotron Lightning（本地/边缘 executor）——不是孤立事件，而是从三个方向同时攻同一个目标：让「一个一直挂着、随时待命、不断跑工具」的 agent 变得经济可行。速度（Cerebras 晶圆级）、价格（Flash 级模型）、部署位置（本地小模型）三个维度同时下探，意味着「常驻 agent」正在从「贵族的玩具」变成「普通人的基础设施」。

Actionable：别再只盯着「哪个模型分最高」做选型。给你的 agent 架构画一条「算力预算曲线」：哪些调用必须用 frontier 模型、哪些可以用 Flash 级、哪些可以在本地跑 executor。一个健康的 agent 应该像一台有变速箱的车——平时用低成本档位巡航，遇到真正的难题才切高档。能把这条曲线设计好的团队，成本效率会比「全用最强模型」的团队高一个数量级。

📌 观点三（简短）：补贴时代的「地板价」开始回收，自部署的护城河更值钱了

DeepSeek 涨价（V4 Flash 输入 +93%）是个值得单独标注的信号。过去一年 agent 开发者享受的「模型越用越便宜」的红利，正在被厂商的盈利压力回收。这对「重 API 依赖」的 agent 产品是个成本风险，对「自部署开源模型」的路线反而是利好——尤其当 Qwen3.8-27B、Muse Glimmer 这类 Apache 2.0 的本地底座越来越多。主观判断：2026 下半年，把关键路径上的模型换成可自部署的开源权重，会从「可选优化」变成「成本对冲的必选项」。
