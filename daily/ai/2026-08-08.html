Cloudflare 给 AI Agent 发「身份证」和「钱包」— Agentic Commerce 基础设施周

Agent 基础设施支付x402Cloudflare

8 月 4 日，Cloudflare 发布了 Cloudflare Wallets 和 cloudflare.pay——一套为 AI Agent 提供可验证数字身份和内置支付钱包的双层方案。AI Agent 现在可以在商家设定的消费限额内自主完成在线购买，使用基于 HTTP 402 状态码的 x402 协议进行稳定币（USDC）微支付。

这不是孤立事件。把这个放到更大的图景里看：

7月14日 — x402 Foundation 在 Linux Foundation 下正式运营，Coinbase 贡献协议，目标成为 AI 支付通用标准
8月2日 — EU AI Act 全面执行，高风险 AI 系统合规义务生效
8月4日 — Cloudflare Wallets 发布，AI Agent 获得身份+支付能力
8月5日 — Sumsub × Sumvin：Know Your Agent (KYA) 框架让 AI Agent 可以「像人类一样花钱」
为什么这是本周最重要的故事：我们在见证 Agentic Commerce 的基础设施层在 同一周内密集落地。身份验证（KYA）、支付协议（x402）、钱包基础设施（Cloudflare）、监管框架（EU AI Act）——四个原本独立的拼图同时就位。这不是巧合。

对 agent 开发者来说，这意味着一个关键拐点：「让 agent 帮你花钱」从技术 demo 变成了有基础设施支撑的产品方向。Cloudflare 的方案特别值得关注，因为它解决了 agent 支付的三个核心难题：(1) 可验证身份——Cloudflare 作为 CA 给 agent 发证书；(2) 消费限额——不是无限花钱，而是可编程的上限；(3) 标准化支付——x402 协议让 agent 调用付费 API 像调用免费 API 一样自然。

但转折在于：Zuckerberg 上个月刚承认 agent 技术进展不如预期。基础设施已经就位了，agent 的能力却还没跟上。这种「管道先于水流」的错配，是我们下一节要仔细分析的。

DeepSeek V4 Flash 0731：预算模型干掉旗舰 Pro 的 Agent 能力——只靠后训练

Agent 能力后训练魔法DeepSeek

7 月 31 日，DeepSeek 将 V4 Flash 升级到 0731 版本。参数没变、架构没变、权重没变——只重做了后训练（post-training）。结果：在全部 9 项 agent benchmark 上超越了自己的 V4-Pro-Preview 旗舰模型。

核心数据：Terminal-Bench 2.1：82.7%（vs Pro 72.1，增幅 44%）；DeepSWE：54.4（vs Pro 的 7.3，增幅 645%）；Cybergym：73.7（vs Pro 67.3）。价格依然是 $0.14/M tokens——284B MoE 架构，仅 13B 活跃参数。

为什么重要——三个层面：
(1) 对 agent 开发者：这个价格+性能组合是目前 agent 工作负载的性价比之王。如果你在用 GPT/Claude 做 tool calling 密集型 agent，切换到 V4 Flash 0731 可能让 token 成本砍到原来的 1/10，agent 能力反而提升。
(2) 对模型研究者：这证明「后训练」的潜力被严重低估了。模型的能力上限可能在预训练时就确定了，但能不能把潜力挖出来，全靠后训练配方。DeepSeek 做到了 645% 的 DeepSWE 提升——这意味着很多「模型不够强」的问题，答案可能是「训练不够好」而不是「参数不够多」。
(3) 对行业格局：预算模型超越旗舰，打破了「更强就得更大更贵」的铁律。这对 Anthropic/GPT 的定价模型是釜底抽薪式的挑战。

Agentic Nesting：把企业应用变成 Agent——多智能体协作新范式

多智能体企业 AIarXiv

本周 arXiv 上出现了一篇值得关注的多智能体论文（arXiv:2608.05159）。作者提出了 Agentic Nesting——一个层级嵌套的多 agent 协作框架，核心思想是将现有的企业应用（SaaS、数据库、ERP 等）直接封装为自主 AI agent，在一个层级化的嵌套结构中协同工作。

为什么重要：当前 agent 框架的普遍思路是「从零构建 agent，然后对接工具」。Agentic Nesting 反其道而行——不新建 agent，而是给已有的企业系统「升维」，让 SAP、Salesforce、Jira 这些本身不是 agent 的系统在嵌套框架中获得 agent 能力。这更贴合企业现实——企业不会为了用 agent 而替换已投资数百万的 ERP 系统。方向上很有洞察力，但论文目前是方法论层面，缺少大规模实验验证。值得继续跟踪。

Shieldstral 后续：为什么「策略自适应」是安全模型的正确方向

小模型安全Mistral

8 月 4 日 Mistral 发布的 3B 安全分类器 Shieldstral 我们昨天已经详细报道。今天补充一个被低估的技术细节：它的策略自适应机制本质上是一种「zero-shot policy interpretation」——不需要为每个审核需求重新微调，推理时直接读一段自然语言写的政策文本就能判断内容是否合规。

这个设计的意义超越了安全分类本身。它验证了一个假设：小模型可以在推理时「加载」任意策略，而不需要在权重中记住它们。如果这个范式能推广到其他领域（合规审查、合同审核、代码规范检查），我们就不需要为每个垂直场景维护一个专用模型了——一个 3B 的「策略解释器」就够了。对 agent 开发者来说，这意味着 agent 的安全层、合规层、策略层都可以是同一个轻量模型的不同 prompt，部署复杂度和成本大幅下降。

Cohere 硬件感知动态推测解码：把推理效率推到硬件极限

推理优化推测解码Cohere

7 月 10 日 Cohere 发布了 Hardware-Aware Dynamic Speculative Decoding (DSD) 技术。与传统的推测解码（用草稿模型预测 token，目标模型验证）不同，DSD 在运行时根据当前 GPU 负载动态调整推测策略——GPU 忙时用更激进的推测，GPU 闲时退回到保守策略。

推测解码的思路不新鲜，但加入「硬件感知」维度是工程上的重要升维。对 agent 开发者来说，这意味着高并发 agent 推理场景（比如同时跑 100 个 agent 实例）可以获得更稳定的延迟和更高的吞吐。虽然还没有开源实现，但这个方向值得所有做 agent 推理基础设施的团队关注。当 agent 从「一次跑一个」变成「一次跑一百个」，推理调度的精细化就是核心竞争力。

💭 深度思考

洞察一：Agentic Commerce 的「管道先于水流」悖论

本周最引人注目的不是某一条新闻，而是一条清晰的时间线：

  • 7月14日：x402 Foundation 启动（支付协议标准化）
  • 8月2日：EU AI Act 执行（监管框架）
  • 8月4日：Cloudflare Wallets 发布（身份+支付基础设施）
  • 8月5日：Sumsub KYA 框架（agent 身份验证）

同一周内，监管、支付、身份、基础设施——agent 自主交易的全部前置条件同时就位。这是一个强烈的信号：业界不是在等 agent 准备好再做基础设施，而是在 agent 还没准备好的时候就把路铺好。

但这也暴露了一个尴尬的事实：Zuckerberg 在 7 月 2 日的内部会议上说 agent 发展「没有如预期加速」。如果这个判断是对的（考虑到 Meta 自己在 Muse Spark 上的投入，他们是最有资格说这话的），那我们现在面临的情况就是：管道已经铺好了，水龙头还没装好。

对 agent 开发者的启示：这不是坏消息。基础设施先行意味着当你做出能真正自主完成交易的 agent 时，不需要再自己去搭支付、身份、合规这些管道——直接用 Cloudflare Wallets + x402 + Shieldstral 就够了。降低的是创业和实验的门槛。当前 agent 能力的瓶颈（规划、推理、自主性）是下一个需要被突破的，但这个突破一旦发生，商业化路径会比一年前顺畅得多。

洞察二：DeepSeek 的后训练魔术——「大模型不够强」可能是个假命题

DeepSeek V4 Flash 0731 的核心数据：DeepSWE 从 7.3 跳到 54.4，增幅 645%。注意：权重没变，参数没变，架构没变。全是后训练的功劳。

这个事实如果在未来几个月被其他团队复现（大概率会），将从根本上改变三个假设：

  1. 「模型能力 = 预训练质量」——错了。后训练可能比预训练更重要。DeepSeek 用事实证明，一个预训练好的模型在不同后训练配方下可以是两种完全不同的模型。
  2. 「更强的 agent 需要更大的模型」——错了。13B 活跃参数的 V4 Flash 在 agent 任务上超越了更大的 Pro。后训练可以弥补甚至超越参数规模的差距。
  3. 「开源模型的瓶颈是预训练算力」——错了。DeepSeek 开源了 Flash 权重，但没说后训练是怎么做的。真正的「秘密配方」可能不是数据量或算力，而是后训练的 recipe。

对 agent 开发者来说，这意味着什么？如果你在选模型做 agent，不要只盯着参数量和 benchmark 总分。关注专门针对 agent 任务（tool calling、代码生成、多步规划）的细分 benchmark，特别是经过了专项后训练的模型。一个 13B 的模型经过正确的后训练，在 agent 任务上可能比一个 100B 的通用模型强 5 倍——DeepSeek 已经证明了这一点。

这也解释了为什么 Anthropic 在 Claude Opus 5（7月24日发布）上特别强调了「为长时间运行的 agent 优化」。后训练正在成为 agent 能力的新战场。
