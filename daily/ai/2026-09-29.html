今日头条：OpenAI DevDay 2026 今日开幕 — Managed Agents 正式成为「云原生一等公民」

P0 今日最重磅 OpenAI · 9月29日 PT 10:00 开幕 · DevDay 官网 · 官方公告 · Managed Agents 预测

一件事：今天是 OpenAI DevDay 2026 开幕日（旧金山 Fort Mason，10:00 PT keynote 公开直播）。从各家提前披露的会场物料看，OpenAI 这次的核心叙事是 「Managed Agents」——把 agent 和它的 runtime 一起搬到 OpenAI 的云上托管，由 OpenAI 负责调度、沙盒、记忆、长程状态。这是 Anthropic 早在 Cowork / Claude Code 已经产品化的形态，但 OpenAI 的入局意味着：agent 不再是「应用内部的一个函数」，而是云平台提供的一个新 primitive。

为什么重要（主编观点）：这次 DevDay 的真实信号不是「GPT-7 来不来」——目前没有任何公开信号指向新一代旗舰模型，「DevDay 必发新模型」是 2024 年的旧范式。真正的信号是 agent layer 在向云平台层迁移：Anthropic 在 claude.ai / Claude Code / Cowork 三处已经验证「云端托管 agent」的体验可行；OpenAI 用 Managed Agents 把它标准化为 API + SDK + Console 三件套。一旦 GA，「自建 agent runtime」会迅速从「值得做」变成「没必要做」——和当年 ECS / Lambda 把自建机房边缘化是同一个剧本。
对你意味着什么：三件可以提前准备的事。① 如果你正在用 LangGraph / OpenAI Agents SDK 自己搭多 agent runtime，今天下午就开始 review Managed Agents 的 SDK 是否能覆盖你的 80% 场景——自研部分留下的应该是「差异化业务逻辑」，而不是「把轮子重造一遍」。② Codex GA 意味着你的 coding agent pipeline 有了 OpenAI 官方的 reference 评估对象，可以用它做 A/B。③ 准备好「agent 状态迁移」方案——一旦 Managed Agents 上线，从本地 session 迁到云端 stateful session 的工具链会变得抢手。

🤖 Agent 前沿

1. JEV-27B 同日发布 — 一个权重同时跑「System 1 + System 2」的开源决策模型

P0 今日新发布 AutoTrust AI · 9月29日 · HF 模型卡 · 官方公告

AutoTrust AI 今天放出 JEV-27B——其继 JEV-9B 之后的第二个开源模型，定位是「自托管 agent 的决策模型」。最大特点是 System 1（快速 typed 决策）+ System 2（深思 reasoning）从同一套权重里出，使用 Blocks-of-Experts 配方。在六组 benchmark（共 26 项）上 9 月 26 日完整评测跑过。

为什么重要：过去 9 个月 agent 框架的默认做法是「快速分类用小模型、复杂推理用大模型」——路由层做两段式调度。JEV-27B 的赌注是 一个 27B 可以同时干两件事，把路由复杂度干掉一半。如果 benchmark 实测可信，意味着 27B 级别就能 cover 自托管 agent 的全部决策需求——H100 / 4090 就能跑得动，对预算敏感的中小团队是结构性利好。
对你意味着什么：① 关注「System 1 / System 2 unified weights」是不是真的有效——6 个 benchmark 还不够看，等社区跑 GAIA、SWE-Bench 再说。② 27B 是「单卡 24GB 勉强 / 双卡 48GB 舒服」的甜蜜点，配合 4-bit 量化能在 M2 Ultra / 4090 本地跑。③ 如果你正在用 classify → route → call big LLM 三段式，先留一个 fallback slot 给 JEV-27B，等评测出来再决定要不要合并。

2. DeepSeek Harness — 「一切皆插件」的开源 agent 运行时，首周 168K stars 还没退烧

P0 DeepSeek · 8月13日发布（仍在持续引爆）· 官方 · 深度解读 · 9 天 183K stars 复盘

DeepSeek 8月13日开源的 DeepSeek Harness (dsh)，MIT 协议，第一周 168K stars / 552K npm 下载，9 天冲到 183K stars。它的核心设计：模型 adapter / 工具 registry / session log / agent loop 全部是可替换的 plugin，连 Claude Code 的核心思想——「harness 是个分层 runtime」——都被它用更激进的「plugin 化」重新表达。

为什么重要：这是「agent 操作系统的标准接口层」的雏形。当 model adapter 是 plugin，就可以无成本切换 GPT-6 ↔ Claude Opus 5.5 ↔ 本地模型；当 tool registry 是 plugin，就可以把 MCP server、自定义 function、shell 全做成一视同仁的 provider。Claude Code 的护城河不是模型，是 runtime；而 DeepSeek 正在用「标准化 runtime 接口」把这个护城河开源。
对你意味着什么：① 如果你在做 coding agent 别再自己写 harness，直接 fork dsh 加 plugin；写 plugin 比写框架容易 10 倍。② 关注 dsh 的 plugin 生态——首批高质量 plugin 会出现一波「个人开发者出圈」的机会窗口。③ dsh 目前还是 developer preview，plugin 协议没稳定前别赌全量，但可以写实验性 plugin 占位。

3. KohakuTerrarium — 「creature + channel」抽象的 agent 框架，本周 GitHub Trending

P0 本周热门 Kohaku-Lab · GitHub · 官方文档 · Trendshift 统计

KohakuTerrarium 的核心抽象是 Creature（单个 agent 单元，含 controller / tools / sub-agents / triggers / prompts / I/O） + Terrarium（运行时引擎，持有 creature graph 的 topology / channels / sessions，本身没有 LLM） + Studio（上层 catalog / session / persistence / API 管理）。Creature 之间通过 channels 和 output wiring 做横向组合，通过 sub-agents 做纵向继承，原生暴露给 Python 的 compose algebra。

为什么重要：和 LangGraph 的「graph as first class」、AutoGen 的「conversation as first class」不同，KohakuTerrarium 押注 「可独立打包、可继承、可嵌套的 agent 单元」。这和 OpenAI DevDay 今天要发布的 Managed Agents 在产品哲学上是同源的——区别在于 KohakuTerrarium 是「自己 host，单元可以打包到 PyPI 复用」。如果 Managed Agents GA，自托管路径会被边缘化；但在它 GA 之前的窗口期，KohakuTerrarium 是少数几个「agent-as-package」形态成熟的开源方案。
对你意味着什么：① 看它的 compose algebra——「Python 原生 agent 组合」是一个被低估的设计点，可能成为 agent 框架的下一代接口。② Studio 层暴露的 REST API 是「快速给非工程师暴露 agent 能力」的现成方案。③ 如果你的业务是多 agent 协作（金融 agent + 法务 agent + HR agent 这种组合），用 KohakuTerrarium 比 LangGraph 更快搭原型。

4. ECC agentic engineering toolkit — 「harness 之上的 operating layer」

P0 本周热门 affaan-m · ECC · 官网 · GitHub fork · Claude Plugin Hub

ECC 自我定位是 「agent harness 之上的 operating layer」——给 coding agents 提供 skills、memory、planning、security 四件套。257k App Install 来自 8月29日–9月11日 owner-verified GitHub 流量。它不取代 Claude Code / Cursor / Windsurf，而是 给它们一个共享的工作层。核心方法论是 eval-first execution（先写 eval 再写实现）+ 15-minute 任务分解 + cost-aware model routing。

为什么重要：这是「agent 工具链正在从 IDE → harness → operating system」演进的明显信号。当 harness（Claude Code、dsh）变多，每个 harness 各自一套 skills / memory / planning 是浪费，ECC 是在抢「harness 之间共享基础设施」的位置。方法论层面，eval-first execution 是和 Vibe Coding 彻底反着走——它要求 先有可测量的 success criterion 再让 agent 写代码。
对你意味着什么：① 把 eval-first 用到自己的 coding workflow 里——哪怕不用 ECC 整套，每个 PR 都先写一个 fail 的 test 再让 agent 实现，输出质量立刻上一个台阶。② 关注 ECC 的 cost-aware model routing 实现——它把「按任务复杂度选模型」产品化了，可以抄思路。③ 如果你正在做 Claude Code 插件市场，现在还来得及占位「harness-agnostic skill」赛道。

5. Claude Sonnet 5.5 杀到 AA Index #2 — 比 Opus 5.5 只差 2 分，价格是 1/2

P0 Anthropic · 9月22日 · AA Index 评测 · OpenRouter 价格

Artificial Analysis Intelligence Index 上，Claude Sonnet 5.5 拿到 56 分，仅比 Opus 5.5（58 分 max）低 2 分，但 Output Tokens per Task 是评测以来最高——意味着 Sonnet 5.5 在相同任务下用更少 token 达到接近顶配的能力。API 定价 $2 input / $10 output per MTok，是 Opus 5.5（$4 / $20）的一半。

为什么重要：这是 agent 开发者的 最强性价比甜点。当 Sonnet 5.5 已经能拿 56 分的时候，绝大多数「thinking + 工具调用」任务根本不需要 Opus 5.5 的额外 2 分。结合昨天日报提到的「分层调度」，Sonnet 5.5 应该成为 agent 默认模型，Opus 5.5 只在最后一步 critical decision 时调用——这是一个能把单次 agent run 成本砍 50% 的具体可执行改动。
对你意味着什么：① 把 Sonnet 5.5 加进你的 model router 的第一档 default；② 重看你的 prompt chain——把 Sonnet 5.5 当成「便宜能用的标准层」，Opus 5.5 只用于 final review / 关键决策；③ Output Tokens per Task 创新高这件事意味着 Agent verbose 优化方向要转向 Sonnet 5.5 的输出风格微调，可以压一轮 token。

💭 深度思考

洞察一：Agent 正在变成「分层操作系统」——harness 之上正在长出 OS 层

把今天的几条 Agent 新闻放在一起看，会发现一个清晰的结构：

  • 模型层：JEV-27B、Claude Sonnet 5.5、Mistral Small 4、Grok 4.7 —— 越来越多人做「Sonnet 级」开源小模型，模型层高度商品化。
  • Harness 层：Claude Code、DeepSeek Harness、CohakuTerrarium —— 提供 runtime、plugin 协议、agent 组合原语。
  • OS 层：ECC（skills / memory / planning / security）、OpenAI Managed Agents（云端托管）、Anthropic Claude Code 插件生态 —— 在 harness 之上提供「跨 harness 共享的工作层」。

这意味着过去 12 个月大家的认知「agent = 一个 LLM + 几个 prompt + 一个 loop」彻底过时了。现在一个 production-grade agent 是 「模型 + harness + OS + 业务逻辑」四层架构。每一层都有开源 / 商业玩家在抢位。

给你的判断：① 押注 OS 层（ECC 类基础设施）或者 业务逻辑层（垂直 agent 应用），避开 纯 harness 层——中间层被两端夹击，毛利最低。② 模型层选 2-3 个（一个顶配 + 一个性价比 + 一个开源小模型），不要超过 4 个，否则 router 复杂度吃光所有收益。③ 评估 agent 框架时，问三个问题：它的 plugin 协议稳定吗？它的 OS 层有第三方吗？它的模型锁定有多深？

洞察二：科学发现成为 Anthropic 和 DeepMind 的「AGI 估值新锚」

Claude 发现 ART、AlphaGenome Atlas 9 billion 变体、WeatherNext 3 商业化——这三件事在 9 月密集发生。这不是巧合，是 AI 实验室集体在「AGI 路线图」上画一个新章节：从「对话能力」到「推理能力」到「科学发现能力」。

对资本市场的含义是：AI 公司的估值不再只看 benchmark，要看「改变了多少人类知识」。Anthropic 用 ART 在「AI 加速基础科学」上抢到第一个明确案例，DeepMind 用 AlphaGenome Atlas 把这条路径标准化。OpenAI 在这条路径上暂时落后——这是 DevDay 2026 今天 如果不发新模型 会显得尴尬的核心原因之一。

给你的判断：如果你是 AI 创业者，做「AI for X」垂类（AI for chemistry / biology / materials）会比「又一个 chat agent」拿到更高估值。如果你是投资人，关注「scientific contribution count」这类 KPI——这会是 2027 年的新估值方法论。
