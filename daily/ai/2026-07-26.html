28.9M 参数的 LLM 跑在 $8 的 ESP32 微控制器上

GitHub: slvDev/esp32-ai 43pts on HN 端侧 AI量化嵌入式

一个惊人的端侧部署 feat：2890 万参数的语言模型完全运行在 ESP32-S3 微控制器上（仅 $8、512KB SRAM），速度约 9.5 tok/s，无需联网。相比之前同类芯片上跑的模型（26 万参数），这是 100 倍的规模飞跃。

关键技术是借鉴了 Google Gemma 的 Per-Layer Embeddings 思路：将 2500 万行的 embedding 表放在慢速 flash 中，每次推理只读取需要的几行。模型以 4-bit 量化存储，仅 14.9MB。

🗣️ 主编观点：这个 demo 的意义远超「在单片机上跑 LLM」本身。它证明了：
① embedding 层的存储-计算分离是端侧 LLM 的可行路径。 大部分参数在 embedding 层且只需读取，这让 flash-as-ROM 的策略极具性价比。
② 9.5 tok/s 对于 IoT 场景已经可用了。 智能家居、可穿戴设备、工业传感器——这些场景不需要生成论文，但需要理解指令、做简单推理。
③ Agent 开发者可以开始思考「全离线 agent」。 如果你的 agent 逻辑足够简单，未来可能完全不需要云 API。

💭 深度思考

📌 今日核心洞察：Agent 开发的「去复杂化」拐点

今天三条最重要的新闻——Anthropic 砍掉 80% system prompt、open-weight AI 的 Kubernetes 时刻、$8 单片机跑 LLM——表面看互不相关，但它们指向同一个深层趋势：

AI 开发正在从「工程复杂」走向「系统简单」。

一年前，构建一个能用的 agent 需要：精心设计的 system prompt、复杂的 few-shot chain、fine-tuned 路由层、GPU 集群。现在呢？Anthropic 告诉你 prompt 可以砍掉 80%；Tobi Knaup 告诉你 open-weight 模型正在成为无需许可的基座；ESP32 的 demo 告诉你推理可以在 $8 芯片上完成。

对 agent 开发者来说，这个趋势的 actionable 含义是：

  1. Less prompt, more capability. 如果你还在用 Claude 4 / GPT-4 时代的 prompt 策略，该升级了。新模型需要的是清晰的目标和约束，而不是详细的步骤指导。
  2. 拥抱 open-weight 作为底层基座。 Kubernetes 时代，没人因为用了「非官方容器运行时」而被开除。同理，在 agent 架构中为 open-weight 模型留出切换空间，会让你在未来 6-12 个月获得巨大的灵活性和成本优势。
  3. 关注端侧 agent 的新可能。 当 28.9M 参数的模型能在 $8 芯片上跑到 9.5 tok/s，物联网 agent 就不再是科幻。家庭的本地语音助手、工厂的离线质检 agent、车机上的隐私对话——这些场景的准入门槛正在崩塌。

📌 被低估的方向：Agent 的「上下文减肥」

Anthropic 的实践表明：模型越强，需要的上下文越少。 但整个 agent 工具链（LangChain、AutoGPT、各种 agent framework）还在往相反的方向走——不断叠加 prompt、memory、RAG 上下文。这里有一个巨大的优化空间：如何系统性地为 agent 做「上下文减肥」？

这可能催生一种新的 agent 优化工具：自动分析 agent 的 prompt 和上下文使用情况，识别冗余，建议精简。就像 webpack 做 tree-shaking，agent 需要「prompt-shaking」。
