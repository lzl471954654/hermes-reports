GLM-5.3 登顶「开源第一」：743B 底座不变，全靠 post-training 把 coding/agent 拉到开源 SOTA

P0 · 模型发布 + Agent 8月14日 · Z.ai（智谱）

Z.ai 昨天发布 GLM-5.3，官方口径是「#1 Open-Source Model」，主打复杂软件工程与 agent 任务。但真正的看点不在「又一个大模型」，而在一个被很多人忽略的方法论细节：GLM-5.3 复用了 GLM-5.2 的 743B base model，所有提升全部来自 post-training，而且官方明确写了训练配方是 「Post-Training Scaling Through Real-World Expert Workflows」——用「真实专家工作流」而不是合成数据/刷题数据来做后训练扩展。

几个硬数字（注意是 Z.ai 自报口径）：

  • Terminal-Bench 3.0：28.3、Agents' Last Exam：28.5——官方称这两个都是开源模型 SOTA；
  • Terminal-Bench 2.1：88.2，逼近 Kimi K3 的水平；
  • CyberGym、AutomationBench 开源领先，官方特别强调「更强的网络安全能力」；
  • 在 Z.ai 自家 Z.ai Code Bench 上比 GLM-5.2 提升 50%。

为什么这很重要：这是过去一周内第三家用「开源权重 + agent 级能力」叫板前沿闭源的中国厂商——DeepSeek V4 Pro 0813（1.6T）前天反超 Opus 4.8，Qwen3.8-Max/27B 本周落地，现在 GLM-5.3 直接打「开源第一」的牌。开源 coding/agent 的「皇冠」已经不是单一赢家，而是三分天下。而 GLM-5.3 贡献的一个新信号是：底座不变、全靠 post-training 就能拿到 50% 提升 + 开源 SOTA——这把竞争焦点从「预训练算力」进一步推向「专家工作流数据 + 后训练配方」。

两个必须标注的 caveat（别被「#1」带节奏）：一是 benchmark 为 Z.ai 自报，尤其 Terminal-Bench 3.0 / Agents' Last Exam 这种硬任务，需要第三方用你自己的 agent 工作流交叉验证；二是开源权重并没有随 API 一起放出——官方口径是「open weights staged behind safety review」，约两周后才上 HF。继承 GLM-5.2 的 MIT 许可定位，但「宣布开源」和「今天能部署」是两回事。

对 Agent 开发者的启示：Z.ai 暴露了 /api/anthropic 端点，Claude Code 等 CLI 可以零改写直接指向 GLM——这是今天就能做的实测路径，不用等权重。如果你在跑长程 coding/terminal agent，值得现在就把 GLM-5.3 接进去和 Claude/DeepSeek 做一次 AB。同时盯紧两点：权重两周后放出时的许可证条款，以及「post-training 只用真实专家工作流」这条路线能否被复现——如果复现得了，它会成为下一轮 agent 模型军备竞赛的标准动作。

NVIDIA Nemotron 3.5 Lightning：30B 总参、3B 激活，专为「永远在线的 agent」打造的开放 MoE

P0 · 小模型/效率 8月12日 · NVIDIA

NVIDIA 发布 Nemotron 3.5 Lightning：30B 总参数的 MoE，每个 token 只激活 3B，定位精确到「always-on agent」——就是那种要一直挂着、持续 gather context、调工具、跑多步任务的 agent。配套的是 NeMo Switchyard 路由架构：frontier 大模型做难任务，Lightning 这类 executor 模型做高频、低延迟的常规任务。规格上给得很足：1M token 上下文、65K 最大输出，提供 NVFP4 和 BF16 两个版本，OpenRouter 上目前免费，Ollama / LM Studio / build.nvidia.com 均已上架。

为什么这是 P0：它精准地戳中了 agent 成本结构里最被忽视的一块——一个常驻 agent 90% 的 token 花在「拿上下文、判断、调工具」这类不需要前沿智力的杂活上。用 3B 激活的模型吃掉这部分，把贵模型留给真正的难点，正是我昨天「深度思考」里写的「算力预算调度」在模型层的落地。3B 激活意味着它在消费级/边缘硬件上也能跑，这对本地部署 agent 的人是个实打实的选项。

对 Agent 开发者的 actionable 建议：这是「frontier + executor 双模型路由」最直接可用的免费素材。你可以今天就试：把 agent 循环里的「工具选择 / 上下文摘要 / 简单问答」这些高频步骤切到 Nemotron Lightning，难任务再回退到 DeepSeek V4 Pro / GLM-5.3。重点验证两件事：function calling 的可靠性（3B 激活能不能稳定出正确的工具调用 JSON）和NVFP4 量化后的真实延迟/内存——这决定了它到底能不能塞进你的边缘设备。

💭 深度思考

📌 观点一：post-training 正在取代 pre-training，成为模型竞争的主战场——而「真实专家工作流」是新的燃料

把今天和昨天连起来看，一个信号越来越清晰。GLM-5.3 底座和 GLM-5.2 完全一样（743B），50% 的 Code Bench 提升 + 开源 SOTA 全靠 post-training，而且训练配方明说了是「真实专家工作流」。DeepSeek V4 Pro 0813 把 Terminal-Bench 从 72 拉到 87.9，也主要靠的是后训练和 agent 数据的迭代。这意味着：「堆更多预训练 token」的边际收益在递减，而「用真实 agent 轨迹 / 专家工作流去后训练」的杠杆在暴涨。

Actionable：如果你在构建自己的 agent，你手里其实握着最值钱的东西——真实运行轨迹（哪一步成功了、哪一步需要重试、人类怎么修正）。别只把它当日志扔掉。做成数据闭环：用 agent 自己的成功/失败轨迹做偏好数据，去微调你选的基础模型，是当下 ROI 最高、且闭源厂商无法替你完成的一步。这比等下一个「更大」的模型更可能成为你的护城河。

📌 观点二：「开源权重」正在从「即时开源」变成「分阶段开源」——选型时要把「权重可得性」当成独立风险

今天几个案例叠加出一个新图景：GLM-5.3 权重「staged behind safety review」约两周后放出；Qwen3.8-Max 也是「API 先上、权重后补」；OpenAI 的 open model 更是一拖再拖、无限期推迟。连「开源」这个标签，都在学闭源那套「安全评审、分阶段放行」的剧本。「宣布开源」和「今天能 self-host」之间的时间差，正在成为一条新的、需要单独评估的风险轴。

Actionable：做技术选型时，别把「官方说了开源」直接等同于「本周能部署」。给你的评估表加一列：权重可得时间 + 许可证条款（是否真的 Apache/MIT）+ serving 资源门槛。对需要「今天就能私有化部署」的场景，Qwen3.8-27B（Apache 2.0、已放权重）这类「即时可得」的选项，反而比「能力更强但权重还要等」的选项更值得先上——因为一个「两周后到货」的模型，对你的生产排期价值约等于零。
