Anthropic 首次公开「研发自动化仪表盘」：Claude 已主导自家 26% 的 AI 研发，3 万个内部 agent 并行运转

P0 · AgentP0 · 效率9月17日

Anthropic Institute 于 9月17日 发布 prototype 版 R&D Automation Index，第一次把「AI 造 AI」从哲学争论变成了可量化的数字：截至 2026 年 8 月，Claude 在约 26% 的被测 AI 研发工作中达到「AI 主导」（Epoch AI 自动化等级 AL4：AI 完成绝大部分任务，人类只做监督与方向性决策），而今年 2 月这个数字还不到 1%；超过 90% 的研发工作至少达到「AI 协作」级。配套披露的还有三个惊人的运营数字：内部并行 agent 规模约 3 万、监控器逐动作审查所有 agent 行为、约 6% 的研发算力投向安全工作。没有任何一项被测工作实现「完全自主」。

为什么重要：过去一年大家都在喊「recursive self-improvement 要来了」，但全是轶事和体感。这是第一家前沿实验室交出分等级、可复核（至少原则上）的自动化遥测数据——等于把 RSI 从叙事变成 KPI。更值得注意的是姿态：Anthropic 同时提出两个行业通用指标（agent oversight 覆盖率、安全算力占比），公开喊话对手跟报。这不是单纯的透明化，而是一次精准的竞争定位——用「我先交卷」倒逼 OpenAI/Google 在同一框架下被比较，并与本周 The Information（9/13）披露的三巨头 FINRA 式标准机构谈判、Amodei 的降速呼吁形成完整闭环：自动化提速 + 自律制度化同步推进。

泼冷水的部分（主观判断）：这些评级「很大程度由 Claude 自己评」——既当运动员又当裁判的问题没有被解决；「主导」的任务权重、任务难度分布也全部未知。26% 更像一条精心选择的宣传口径下界。但即便打个对折，「八个月从 1% 到 13%+」的斜率本身，就足以改变你对未来 12 个月 agent 自动化天花板的预期。

对 agent 开发者：真正的信号藏在运营数据里——3 万 agent、逐动作监控、6% 算力给安全，这就是前沿实验室眼中「生产级 agent 舰队」的标准配置。你现在的 agent 项目里，eval 和监控占多少工程量？如果答案是零，你落后于行业默认线。可关注：agent oversight 工具链（trace 审计、行为异常检测）大概率成为下一个工具层爆发点。

① OpenAI 发布 Astra for Law：不是新模型，而是一条 2.3 亿 URL 的法律索引

P0 · Agent9月17日发布，18日持续发酵

Astra for Law = GPT-6 Astra + 法律分析指令 + 全新 Legal Search Index（覆盖美国判例法、成文法、法规、法院规则与行政裁决，超过 2.3 亿 URL，基于开源的 CourtListener 数据，来源每日更新），外加 73 个法律插件与 law-firm 工作流，通过 Trusted Access 向选定律所推送（与三家精英律所共同开发）。OpenAI 自测：54% vs 通用联网搜索的 38.7%。

意味着什么：注意产品形态——没有预训练新模型、没有 fine-tune 宣传，护城河全部建在「领域索引 + 指令 + 工作流 + 交付管道」上。这是 vertical agent 的范式定型：模型层商品化之后，数据管道就是新的模型。54% 听起来不高，但法律检索是容错率极高的领域，这个数字说明「能当助理、不能替合伙人」——OpenAI 自己也这么定位。另一个细节：商业产品跑在开源数据（CourtListener）上，说明 open data × frontier model 的组合拳已经被验证可商业化。

对 agent 开发者：你在做的垂直 agent，与其追问「用哪个模型」，不如先回答「我的 2.3 亿 URL 索引是什么」。领域语源的独家性 + 每日更新机制 + 领域评测集，才是可防御的部分。

① PrismML Ternary Bonsai 2 27B：27B 多模态模型压进 5.9GB，三值权重保住 98.2% 性能

P0 · 效率9月17日

PrismML 发布基于 Qwen3.8 27B 的三值（ternary，语言权重仅取三个离散值）版本 Bonsai 2 27B：磁盘占用 5.9GB，聚合基准 83.9 vs 全精度 85.4（保留 98.2%），且评测套件覆盖推理、数学、代码、指令跟随、视觉和 agentic tool use。GGUF 已上 Hugging Face（prism-ml/Ternary-Bonsai-2-27B-gguf），Apple Silicon 有 MLX 版（含 vision tower 共 8.6GB），模型卡 Metal 数据约 28 tok/s（M5 Pro）。

意味着什么：BitNet 式 1.58-bit 梦想正在以「对开源模型做后训练三值化」的路径落地。27B 多模态 + tool use 塞进一部手机的存储空间，这件事的产业含义大于任何单点 benchmark：当权重成本趋近于零，端侧 agent 的瓶颈从「能不能跑」变成「tool 生态和内存带宽」。需要冷静的地方：成绩是官方自报，视觉塔并未三值化，长上下文/多轮 agent 场景的退化程度未知——「98.2% 保留」是聚合口径，不代表你关心的那个 benchmark 没掉。

对 agent 开发者：端侧 tool-calling 模型的可用性清单又多了一员。如果你的 agent 场景是隐私敏感/离线优先，27B 三值模型 + GBNF 约束 + MCP 本地工具，已经是一条能跑通的完整栈。

② DeepSeek V4.1-Flash 的余波：当 KV cache 压到 890 字节/token，「记忆层」还需要吗？

P1 · 效率模型 9月10日发布，争论本周持续

DeepSeek V4.1-Flash（552B MoE 多模态，MIT 协议，1M 上下文）用 CED split、CSA2、FP4 量化、SWA 消除四招把 per-token 记忆压到 890 字节，约为前代的 1/4–1/8。本周真正的看点是后续争论：mem0 发文《890 Bytes Per Token, Zero Bytes of Persistent Memory》正面回应「长上下文便宜到极致后，外挂记忆层是否还有存在必要」——答案是 YES，理由是上下文 ≠ 状态：检索成本、注意力稀释、跨会话持久性都不是 KV cache 能解决的。

意味着什么：效率革命的主战场正从权重（Bonsai 的三值化）转移到状态（KV/agent state）。当模型权重大小不再是门槛，「每任务字节成本」会成为 agent 架构的第一性指标。mem0 的反驳本身就是信号——记忆层厂商开始把超长上下文模型当头号假想敌来写文章了。

对 agent 开发者：值得做一个简单测算：你的 agent 单任务平均产生多少 token 的上下文？按 890B/token 级别的 KV 成本与 memory 层方案的检索延迟/存储成本各自建模，答案可能会改变你的 compaction 策略。

💭 深度思考

1. 这一周真正的大事，是「自我改进」和「自我约束」被同时制度化了。把时间线排开：9/13 三巨头标准机构谈判曝光 → 9/16 OpenAI 事故披露制度 + 六起 misalignment 报告 → 9/17 Anthropic 交出 26% 自动化仪表盘。三家实验室不约而同在做同一件事：给「AI 造 AI」装上仪表盘、黑匣子和年检制度。这不像巧合，更像对「今年夏天多起 agent 失控测试事件」（CNN 语）的集体回应——与其等监管者上门，不如先定义「负责任」的标准并抢占解释权。被市场低估的判断：安全基础设施（监控、披露、审计、认证评测）正在成为与模型能力同速增长的平行市场。Anthropic 6% 的安全算力、OpenAI 的 alignment 博客、以及未来 FINRA 机构的评测采购，都会变成真金白银的工具链需求。做 agent 基础设施的人，这可能是比「更好的 agent 框架」更大的空位。

2. 效率叙事正在合流：权重、状态、渠道三条战线同时压缩成本。本周三个互不相干的数字放在一起看很有意思：Bonsai 2 把 27B 权重压到 5.9GB（权重成本 → 存储成本），DeepSeek 把 KV cache 压到 890B/token（状态成本 → 带宽成本），Mozilla×Mistral 把小模型预装进浏览器（分发成本 → 预装渠道，昨日报已述）。三者叠加的含义：「跑一个不错的模型」正在从资本问题降级为工程问题。对 agent 开发者的 actionable 建议——从今天起用「每任务字节经济学」做架构决策：上下文里每一个 token 都有真实的字节账单，compaction、KV 复用、端云协同路由不再是优化项，而是产品设计本身。当 26% 的研发由 AI 主导、5.9GB 装下 27B，两种曲线相交的那一天，才是真正的拐点。
